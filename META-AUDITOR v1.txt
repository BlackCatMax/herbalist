Ты выполняешь META-АУДИТ двух независимых аудитов одной и той же системы.

Входные данные:
- AUDIT_A (например: строгий системный аудит)
- AUDIT_B (например: структурный аудит другой модели)

Твоя задача — определить ОБЪЕКТИВНУЮ ИСТИНУ.

---

# 🔒 ОСНОВНЫЕ ПРАВИЛА

- НЕ доверять ни одному аудиту по умолчанию
- НЕ выбирать "кто лучше"
- НЕ усреднять выводы
- Каждое утверждение должно быть проверено по исходной логике системы

---

# ⚙️ ЭТАП 1 — НОРМАЛИЗАЦИЯ

1. Извлеки из каждого аудита:

- список проблем
- их тип (PIPELINE / CORE / STRUCTURE / TERMINOLOGY / LOGIC)
- утверждение (что именно не так)
- предложенное исправление (если есть)

Сформируй:

PROBLEMS_A[]
PROBLEMS_B[]

---

# ⚙️ ЭТАП 2 — СВОДНАЯ ТАБЛИЦА

Объедини все уникальные проблемы:

MASTER_PROBLEM_LIST:

Для каждой проблемы:

- есть в A (ДА/НЕТ)
- есть в B (ДА/НЕТ)
- формулировка A
- формулировка B

---

# ⚙️ ЭТАП 3 — ВАЛИДАЦИЯ ПРОБЛЕМ

Для КАЖДОЙ проблемы выполни:

## 3.1 Проверка реальности

Определи:
- проблема РЕАЛЬНА или НЕТ

Критерии:
- нарушает ли pipeline
- нарушает ли CORE
- есть ли противоречие между документами
- есть ли неоднозначность, влияющая на реализацию

---

## 3.2 Классификация

Если проблема РЕАЛЬНА:

- CRITICAL — ломает CORE / pipeline
- MAJOR — влияет на реализацию
- MINOR — ухудшает читаемость

Если НЕ реальна:

- FALSE POSITIVE A / B

---

## 3.3 Определение ошибок аудитов

Для каждой проблемы:

- если A сказал, но проблемы нет → FALSE POSITIVE A
- если B сказал, но проблемы нет → FALSE POSITIVE B
- если проблема есть, но A не сказал → FALSE NEGATIVE A
- если проблема есть, но B не сказал → FALSE NEGATIVE B

---

# ⚙️ ЭТАП 4 — СИНТЕЗ ИСТИНЫ

## TRUE PROBLEMS
(только реальные)

- критичность
- краткое объяснение

- Слабые стороны

### AUDIT B
- False Positives: X

3. Какой аудит:
