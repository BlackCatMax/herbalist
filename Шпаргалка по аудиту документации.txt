ПРОМПТ 1

Ты выполняешь строгий технический аудит трёх документов:

1. technical.md — формальная спецификация системы
2. design.md — дизайн-описание (игровая логика, поведение)
3. glossary.md — определения терминов

Твоя задача — НЕ пересказывать и НЕ улучшать текст,
а выявить ВСЕ несоответствия между документами.

---

# ОСНОВНЫЕ ПРАВИЛА

- НИКАКИХ обобщений
- НИКАКИХ "в целом совпадает"
- ТОЛЬКО конкретные расхождения
- Если есть сомнение — считать это проблемой
- Ничего не додумывать, работать строго по тексту

---

# ЧТО ПРОВЕРЯТЬ

## 1. Терминология (glossary ↔ остальные)

Для каждого термина:

- Совпадает ли определение?
- Используется ли термин одинаково?
- Есть ли термины, используемые в technical/design, но отсутствующие в glossary?
- Есть ли термины в glossary, которые нигде не используются?

Формат:

[TERM MISMATCH]
Термин: <name>

glossary:
<определение>

technical:
<как используется>

design:
<как используется>

Проблема:
<конкретное расхождение>

---

## 2. Пайплайн (design ↔ technical)

Проверить:

- совпадает ли порядок этапов
- совпадает ли наличие этапов
- совпадает ли логика этапов

Формат:

[PIPELINE MISMATCH]

design:
<описание>

technical:
<описание>

Проблема:
<в чём расхождение>

---

## 3. Формулы и вычисления

Проверить:

- одинаковы ли формулы
- одинаковы ли переменные
- нет ли скрытых различий (например: clamp есть в одном месте, нет в другом)

Формат:

[FORMULA MISMATCH]

Формула: <название>

technical:
<формула>

design:
<описание/формула>

Проблема:
<различие>

---

## 4. Инварианты и ограничения

Проверить:

- одинаковые ли ограничения (clamp, диапазоны, “нет ветвлений” и т.д.)
- нет ли противоречий

Формат:

[CONSTRAINT MISMATCH]

Ограничение: <описание>

technical:
<что сказано>

design:
<что сказано>

Проблема:
<конфликт>

---

## 5. Поток данных

Проверить:

- где создаётся Δ
- где используется Δ
- где создаётся distortion
- где используется memory

Формат:

[DATA FLOW MISMATCH]

Элемент: <Δ / distortion / memory>

technical:
<описание>

design:
<описание>

Проблема:
<расхождение>

---

# ДОПОЛНИТЕЛЬНЫЕ ПРОВЕРКИ

Обязательно найти:

- дублирующие определения
- несовместимые утверждения
- “скрытые” зависимости (например, pressure используется, но не определён)
- расхождения в порядке вычислений

---

# ФОРМАТ ВЫВОДА

1. Список ВСЕХ проблем (без пропусков)
2. Каждая проблема — отдельный блок
3. Без объединения разных проблем в одну

---

# ЗАПРЕЩЕНО

- переписывать документы
- предлагать улучшения
- “исправлять” текст
- делать выводы без цитат

---

# ЦЕЛЬ

Найти ВСЕ расхождения между:

technical.md ↔ design.md ↔ glossary.md

Даже если их очень много.


ПРОМПТ 2

Перепроверь свой ответ.
Найди пропущенные несоответствия.


ПРОМПТ 3

Ты получил результат строгого аудита несоответствий между документами:

- technical.md
- design.md
- glossary.md

Твоя задача — предложить КОНКРЕТНЫЕ действия по исправлению,
чтобы привести документы к полной согласованности.

---

# ОСНОВНЫЕ ПРАВИЛА

- НЕ пересоздавать систему
- НЕ менять логику без необходимости
- НЕ “улучшать” дизайн
- НЕ переписывать всё с нуля

Твоя задача — МИНИМАЛЬНЫЕ правки, которые устраняют расхождения.

---

# ПРИНЦИП ПРИОРИТЕТА

Если есть конфликт:

1. technical.md — источник истины для формул и пайплайна
2. glossary.md — источник истины для терминов
3. design.md — должен быть приведён в соответствие

Если есть сомнение — НЕ решать самостоятельно, а пометить.

# ДОПОЛНИТЕЛЬНЫЕ ТРЕБОВАНИЯ

1. НЕ объединять несколько проблем в одну правку
2. НЕ делать “общие рекомендации”
3. Каждое изменение должно быть атомарным
4. Все изменения должны быть совместимы друг с другом
