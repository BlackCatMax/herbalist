# CORE ASSUMPTION (КРИТИЧЕСКИЙ ПРИОРИТЕТ)

Существует слой CORE:

* фундаментальные правила
* инварианты
* архитектурные принципы

ВСЕ системы ОБЯЗАНЫ:

* подчиняться CORE
* не противоречить CORE
* не обходить CORE
* не переопределять CORE

Любое нарушение CORE = **CRITICAL ERROR**

# 🧠 ЭТАП 1 — ПОЛНЫЙ СИСТЕМНЫЙ АУДИТ

## 1.1 Междокументные проблемы

Найти ВСЕ:

* логические противоречия
* расхождения определений
* конфликты pipeline
* расхождения формул
* несовпадения ролей систем

## 1.2 Внутренние проблемы

Для КАЖДОГО документа:

* противоречия между разделами
* сломанные инварианты
* неверный порядок этапов
* неиспользуемые или висящие параметры
* дубли логики

## 1.3 CORE VIOLATIONS (КРИТИЧНО)

* обход CORE
* скрытые механики
* переопределение CORE
* системы вне общей модели
