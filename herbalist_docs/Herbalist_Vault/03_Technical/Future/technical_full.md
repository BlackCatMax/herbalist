# Herbalist — Техническая спецификация v2.3.2 (с интеграцией GDD)

## 🔒 1. Общие принципы (CORE)

> **Из GDD:** *«Мир игры представлен как единая система состояния. Игрок не взаимодействует с реальным состоянием напрямую. Любое действие основано на искажённом восприятии.»*

### 🔒 1.1 Представление состояния

S_real(x, y, t) = (d, m, Meta)
- `d` — **нормированный 4D-вектор направления** (body, mind, spirit, nature). Определяет качественный профиль состояния. **Интерпретация GDD:** Это «архетип» вещи или места, близость к одной из фундаментальных стихий (телесное, ментальное, духовное, природное). Игрок ощущает это через описания: «живое», «чистое», «мутное», «тяжёлое».
- `m` — **скалярная величина (magnitude)**. Интенсивность/насыщенность состояния. **GDD:** «Сила» травы, яркость проявления сущности. Воспринимается как «слабое/сильное», «едва заметное/мощное».
- `Meta` — **набор модификаторов поведения** (см. раздел 2). **GDD:** Скрытые параметры, влияющие на «характер» состояния: его чистоту, устойчивость, склонность к искажениям.

#### 🔒 1.1.1 Алатырь (S₀) как эталонное состояние

**GDD:**
> *«В системе существует эталонное состояние — S₀ (Алатырь). Это абстрактное состояние полной согласованности... Любое текущее состояние может быть рассмотрено как отклонение от S₀.»*
> *«Distance(BiomeState → S₀) определяет степень устойчивости, уровень Morok и читаемость мира.»*

S₀ = (d₀, m₀, Meta₀)   // Эталонный вектор (например, d₀ = (0.5, 0.5, 0.5, 0.5) норм., m₀ = 0.5*M_max)
Distance(S, S₀) = w1 * ||d - d₀|| + w2 * |m - m₀| + w3 * ||Meta - Meta₀||

Эта метрика должна **напрямую влиять** на:
- `Morok` (интенсивность `λ_raw`).
- `world_coherence` (как `1 - Distance`).
- Сложность интерпретации для игрока (реализуется через UI на основе `Distance`).

### 🔒 1.2 Восприятие

S_perceived = Distort(S_real, Morok)

> **GDD:** *«Игрок не имеет прямого доступа к реальному состоянию мира. Восприятие формируется как искажённая версия: S_perceived = Distort(S_real, Morok).»*
Игрок взаимодействует **только** с `S_perceived`. Функция `Distort` моделирует **Морок** — системное искажение, делающее мир ненадёжным, загадочным, соответствующим эстетике фолк-хоррора.

### 🔒 1.3 Pipeline системы

Единственный допустимый поток изменений (из GDD):

S_real → Distort(Morok) → S_perceived → Action → Intent_player → Intent_system → ΔS → S_real'

> **GDD:** *«Игрок действует на основе восприятия, система изменяет реальное состояние, результат снова искажается перед восприятием.»*

### 🔒 1.4 Намерение

Intent_player = F(Action(S_perceived))
Intent_system = F(Action(S_real))
ΔIntent = Distance(Intent_player, Intent_system)

> **GDD:** *«Намерение не задаётся напрямую. Оно формируется как структура действия. Игрок создаёт намерение из искажённого восприятия, а система интерпретирует его относительно реального состояния. Это создаёт фундаментальный разрыв — источник неожиданных результатов.»*

### 🔒 1.5 Инварианты трансформации

(Математические гарантии целостности системы.)
> **GDD:** *«Запрещено вводить независимые системы. Любая новая механика должна быть выражена через изменение BiomeState.»*

## 🔒 2. Структура состояния (CORE)

### 🔒 2.1 Базовая структура

S_real = (d, m, Meta)
- `d = (body, mind, spirit, nature)`, `|d| = 1` — **GDD:** Оси соответствуют четырём аспектам мироустройства в языческом мировоззрении. Конфликты между осями (например, body vs spirit) порождают нестабильность.
- `m ∈ [0, M_max]` — **GDD:** «Жизненная сила», «насыщенность».
- `Meta` — словарь модификаторов (все значения в диапазоне `[0,1]`, кроме особо оговоренных):
    - `potency` — **мощность**: масштабирует силу всех Δ. **GDD:** «Внутренняя сила» ингредиента.
    - `purity` — **чистота**: подавляет шум и искажения. **GDD:** Соответствует понятию «чистоты» в народных поверьях.
    - `stability` — **устойчивость**: сопротивление изменениям. **GDD:** Насколько состояние «держит форму».
    - `resonance` — **резонанс**: усиливает совпадающие направления. **GDD:** «Сродство» компонентов.
    - `corruption` — **порча**: усиливает негативные эффекты. **GDD:** Накопленная «скверна».
    - `distortion ∈ [0,1]` — **локальный уровень искажения** (входной параметр для Morok). **GDD:** Мера присутствия Морока в данной точке.

### 🔒 2.2 Разделение реальности и восприятия

S_perceived = Distort(S_real, Morok)

> **GDD:** *«Все наблюдаемые признаки среды являются частью воспринимаемого состояния мира, а не его объективного представления. Это означает, что одни и те же признаки могут соответствовать различным фактическим состояниям.»* Программист должен гарантировать, что UI, описания и визуальные эффекты строятся исключительно на `S_perceived`.

## 🔒 3. Канонический Pipeline (CORE)

**GDD (пайплайн мира):** *«Игровой процесс разворачивается как последовательность переходов: наблюдение → интерпретация → выбор точки воздействия → сбор → преобразование → формирование результата → применение → изменение состояния → новое наблюдение.»*

Технический pipeline (разделы 4-14) является прямой реализацией этого цикла. Каждая стадия ниже соответствует определённому этапу из GDD.

### 🔒 3.1 Harvest (сбор ресурса)

Функция Harvest(biome_coords, resource_type, timestamp) возвращает S_resource:

S_resource = Base(type) + k_biome * (Biome.params - S₀) + k_condition * Condition.modifier

где:
- Base(type) — из таблицы **8.4.1 (design_full.md)**
- Biome.params — текущее S_real в точке сбора
- Condition.modifier — сумма модификаторов из таблиц 8.5.1–8.5.4
- k_biome = 0.6 (по умолчанию), k_condition = 0.4

## 🔒 4. Fold (агрегация) (CORE)

`S₀ = fold(inputs)`
> **GDD:** *«Игрок объединяет ресурсы в процессе преобразования. Он выбирает состав, определяет порядок, формирует структуру процесса.»*
`fold` — математическое выражение этого объединения. Веса `w_i` (⚙️ SEMI) отражают, насколько «правильно» (в контексте народных знаний) игрок сочетает ингредиенты, учитывает фазы луны и т.п.

Функция fold вычисляет агрегированный вектор состояния из списка ресурсов (каждый с параметрами S_resource). 
Порядок ресурсов влияет на веса: первые ресурсы имеют больший вес (коэффициент 1.0, далее затухание 0.8, 0.6...).

---

## 🔒 5. Δ (приращение) (CORE)

`ΔS = delta(S₀)`
> **GDD:** *«Намерение не гарантирует результат, а задаёт его направленность. Оно проявляется не в процессе, а в том, как результат фиксируется и воспринимается системой.»*
Вычисление Δ определяет **направление и силу изменения**, которое будет привнесено в мир. `BOOTSTRAP_GAIN` и `Alignment` моделируют, насколько хорошо «намерение» игрока
согласуется с текущим состоянием мира и накопленным искажением.

ΔS = delta(S_aggregated, Intent_system, BiomeState)
	где Intent_system вычисляется из последовательности действий (см. раздел 1.4). 
	
Intent_system может модифицировать ΔS: увеличивать или уменьшать компоненты stability, distortion, purity в зависимости от согласованности.

## 🔒 6. Context (CORE)

> **GDD:** *«Каждое место влияет на свойства ресурсов, изменяет поведение процессов, задаёт уровень риска, определяет степень проявления Morok.»*
Функция `context` вычисляет коэффициенты `k_axis` и `k_meta` на основе параметров биома (`toxicity`, `fertility`, `moisture` и т.д.). Это реализация идеи, что **одно и то же действие в разных местах приводит к разным результатам**.

## 🔒 7. Water (CORE)

> **GDD:** *«Вода — один из самых чувствительных индикаторов состояния мира. Она быстро реагирует на Morok, отражает локальные искажения, может усиливать или гасить эффекты.»*
Функция `water` вносит аддитивное воздействие, моделирующее перенос свойств влагой. **Инвариант (не изменяет resonance и distortion)** подчёркивает, что вода — переносчик, но не источник глубинных изменений.

При использовании воды в алхимии её параметры S_water добавляются к агрегированному состоянию на этапе fold с весом, зависящим от количества воды.

### 7.1 Параметры воды по биомам

Дефолтные параметры воды для каждого типа биома (при сборе в нейтральных условиях) определены в **design_full.md, раздел 8.3.1**.
При реализации функция `water(S_real, biome_type)` должна использовать эти значения как базовые для `S_water`.
В процессе игры параметры воды могут изменяться под действием Morok и Заряны, а также под влиянием капищ (см. раздел **8.12 design_full.md**).

### 🔒 8 Фрагменты памяти Заряны

**Описание в GDD:**
> *«Фрагменты памяти Заряны влияют на восприятие: уточнение интерпретации происходящего, появление новых смысловых связей, более согласованное восприятие изменений. Они не дают информации напрямую, но уменьшают искажение интерпретации.»*

- Ввести глобальный параметр `Zaryana_Clarity` (накапливается при получении фрагментов).
- Модифицировать функцию `Distort`:

  effective_distortion = distortion * (1 - Zaryana_Clarity)
  S_perceived = Distort(S_real, effective_distortion)
  
- Это **не изменяет** `S_real`, но напрямую снижает «туман войны» для игрока, улучшая читаемость UI и точность его внутренней модели.

## 🔒 9. Axis Sign Modifiers (CORE)

> **GDD:** *«Конфликты параметров могут усиливать друг друга, ослаблять или вступать в противоречие. Конфликт не является ошибкой, а формирует напряжение внутри системы.»*
Блок `axis_sign` вычисляет `neg` (негативность), `harmony` и прямые конфликты `C_bs` (тело vs дух), `C_mn` (разум vs природа). **GDD:** Это проявление внутренней борьбы, характерной для мира, где «всё не так, как кажется».

---

## 🔒 10. Interaction Rules (CORE)

> **GDD:** *«Все системы взаимосвязаны: сбор формирует параметры ресурсов, параметры влияют на алхимию, алхимия изменяет состояние мира...»*
`Interaction` моделирует сложные обратные связи между параметрами. **Meta coupling** с snapshot-семантикой гарантирует, что все взаимовлияния происходят одновременно, без паразитных петель.

---

## 🔒 11. Morok (искажение Δ) (CORE)

> **GDD:** *«Morok — это системное искажение мира, которое нарушает привычные причинно-следственные связи. Это не случайность, а фундаментальное изменение, влияющее на все проявления мира.»*
Функция `morok_effect` является **сердцем непредсказуемости** системы. Она применяет нелинейное искажение к вычисленному `Δ`, из-за чего результат алхимии может радикально отличаться от ожидаемого, особенно в зонах с высоким `distortion`. **GDD:** *«Ошибка становится частью истории и влияет на дальнейшие процессы.»*

---

## 🔒 12. Zaryana (структурирование) (CORE)

> **GDD:** *«Заряна представляет собой процесс стабилизации, который снижает искажение, повышая согласованность системы. Это не отдельная механика, а естественная часть того же процесса, что и Morok.»*
Функция `zaryana` усиливает выраженные компоненты и подавляет слабые, делая состояние более «чётким». **Важное уточнение из GDD:** Zaryana **не устраняет Morok полностью**, а делает систему более **читаемой и предсказуемой**, давая игроку больше контроля. В математике это отражено тем, что `distortion` не изменяется.

## 🔒 13. Пространственная структура мира (BiomeState)

### Исторические параметры
> **GDD:** *«Состояние мира накапливает изменения. Эти изменения взаимодействуют, усиливают друг друга, формируют устойчивые структуры. История состояния влияет на будущие реакции системы.»*
Параметры `accumulated_distortion`, `stability_memory`, `history_purity` являются прямой реализацией «памяти мира».

### 13.1 Инициализация биомов и капищ

Начальные состояния `S_real(x, y, 0)` для каждого участка карты определяются по таблице дефолтных параметров биомов, описанной в **design_full.md, раздел 8.1.1**.
В процессе игры эти значения изменяются согласно пайплайну (раздел 13) и накапливаются в исторических параметрах (accumulated_distortion, stability_memory, history_purity).

Конкретные значения модификаторов для каждого типа капищ (Родовое, Лесное, Водное, Каменное, Пограничное, Забытое) приведены в **design_full.md, таблица 8.12.1**.
При программной реализации модификаторы применяются к `S_real` ячейки, если в радиусе есть восстановленное капище соответствующего типа.

## 🔒 14. События (Events) как эмерджентные явления

**Описание в GDD:**
> *«События — это не внешние скрипты. Они возникают из состояния: Event = Emergent(BiomeState + Time + Conditions).»*
> *«События влияют на ΔS_modifier и на S_perceived (через Morok).»*

1. **Условия генерации** (🔒 CORE):
   ```text
   P_event = sigmoid( (gradient_magnitude - THRESHOLD_GRAD) + (accumulated_distortion - THRESHOLD_DIST) + season_factor )
   ```
2. **Типы событий и их эффекты** (⚙️ SEMI):
   - `ANOMALY`: `ΔMeta.corruption += value`
   - `PURGE`: `ΔMeta.purity += value`
   - `BLOOM`: `ΔBiome.fertility += value`
3. **Влияние на восприятие**: Событие временно увеличивает `Morok` для `Distort` функции, даже если реальное состояние изменилось незначительно (создаёт «наваждение»).

## 🔒 15. Прогрессия и финальное состояние (CORE)

> **GDD:** *«Прогрессия связана с приближением состояния мира к эталонному состоянию S₀ (Алатырь). Чем ближе состояние мира к S₀, тем выше устойчивость, тем ниже уровень искажения, тем точнее интерпретация.»*
Функция `world_coherence` вычисляет, насколько мир в целом приблизился к состоянию **Алатыря**. `is_buyan_accessible` определяет, достигнуто ли состояние **Буяна** — «места перехода», где игрок может повлиять на судьбу Заряны. **GDD:** *«Буян не является физическим местом, а состоянием, которое должно быть достигнуто через изменения мира.»*

## 🔒 16. Storage Layer (инвентарь и порча)

> **GDD:** *«Хранение в игре не является пассивным сохранением результата. Игрок сохраняет не объекты, а зафиксированные конфигурации состояния, которые продолжают изменяться в процессе хранения.»*
Использование **того же pipeline** с масштабированием по времени (`scale_delta`) моделирует «порчу» (Morok leakage) как естественное продолжение жизни предмета. **GDD:** *«Порча не является отдельным эффектом. Это продолжение действия Morok в условиях хранения.»*
