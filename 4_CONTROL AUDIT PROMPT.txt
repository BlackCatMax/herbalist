# 🎯 ЦЕЛЬ

---

# 🔒 ОСНОВНЫЕ ПРАВИЛА

- НЕ доверяй ни одному аудиту
- НЕ усредняй выводы
- Проверяй всё по документам
- Игнорируй исправленные проблемы (если они уже устранены)
- Не переоценивай формулировки, если логика не нарушена

---

# ⚙️ ЭТАП 1 — ПРОВЕРКА CORE

Проверь:

- есть ли нелинейности вне Morok
- есть ли более одного Final Clamp
- есть ли скрытые этапы pipeline
- нарушается ли порядок применения этапов

Вывод:
- CORE OK / CORE BROKEN

---

# ⚙️ ЭТАП 2 — PIPELINE

Определи реальный pipeline из technical.md.

Проверь:

- одинаков ли он во всех документах
- есть ли противоречия
- есть ли дубли или альтернативные версии

ВАЖНО:
Если есть разные уровни детализации (например:
- канонический pipeline
- детализация этапов
- расширенный цикл)

→ это НЕ ошибка, если они не противоречат друг другу.

---

# ⚙️ ЭТАП 3 — ПРОВЕРКА ПРОБЛЕМ ИЗ АУДИТОВ

Для КАЖДОЙ проблемы из AUDIT_A и AUDIT_B:

1. Проверить по документам:
   - проблема РЕАЛЬНА или НЕТ

2. Если проблема:
   - уже исправлена → IGNORE
   - всё ещё есть → VALID

3. Классифицировать:
   - CRITICAL (ломает CORE/pipeline)
   - MAJOR (влияет на реализацию)
   - MINOR (документация)

---

# ⚙️ ЭТАП 4 — ПОИСК ПРОПУЩЕННЫХ ПРОБЛЕМ

Проверь самостоятельно:

- отсутствующие разделы
- битые или неточные ссылки
- неиспользуемые параметры
- разрывы потока данных
- неоднозначные формулировки, влияющие на реализацию
