# План реализации UI — свод двух ресёрчей в конкретные шаги

Сводит `DESIGN_Diegetic_UI_Research.md` (проверка примеров диегетического
UI + разбор ненадёжного интерфейса) и `DESIGN_KCD2_Alchemy_Research.md`
(разбор системы варки Kingdom Come: Deliverance II) в единый план,
привязанный к уже существующему коду (`03_Technical/Current/UI_Current.md`)
и уже принятой, финальной философии (`02_GDD/07_UX.md` — этот документ её
**не пересматривает**, только реализует). Черновик-план, не канон, как и
оба исходных ресёрча.

**Текущая точка старта** (`UI_Current.md`, 2026-09-06): реальный UI есть —
`UInventoryWidget`/`UAlchemyTransferWidget`/`UItemTooltipWidget`/
`UJournalLogWidget` работают, но большинство систем, добавленных после
Фазы 4, управляется голой Exec-консолью, без диегетической подачи вовсе.
План ниже — не «построить UI с нуля», а «взять уже рабочий каркас и
довести его до принципа `UI = Representation(S_Perceived)`, который пока
реализован частично и местами противоречиво (см. 1.1 ниже)».

---

## 0. Сквозные решения (из обоих ресёрчей разом)

Прежде чем идти по системам — три решения, которые касаются всех разделов
ниже и должны быть приняты один раз, не по системе за системой.

**0.1. Не всё должно врать одинаково.** (Диегетический ресёрч §3, урок из
Subnautica/Darkest Dungeon.) У Herbalist уже есть заявленный честный якорь
— состояние Заряны (`07_UX.md §7.2/§7.12`, «наблюдается напрямую»).
Решение: явно зафиксировать **второй** честный якорь — факт наличия
предмета в инвентаре (слот не исчезает и не задваивается от Морока,
`PerceiveValue` не трогает `Amount`, только `State`) — это уже так в коде,
план ниже просто не должен эту гарантию где-либо случайно нарушить.
Всё остальное (название, иконка, тултип, реплики хозяев места, показания
котла) — честный кандидат на искажение.

**0.2. Скупая сенсорная подача, число — только в конце, с явным
уроком KCD2.** (KCD2-ресёрч §3, §6.1.) Подтверждённый рабочий прецедент:
никакого прогресс-бара во время процесса, только пар/цвет/звук, тир —
по готовности. Уже совпадает с `07_UX.md §7.2.3`/`Alchemy.md`. НО KCD2 же
даёт задокументированный (PC Gamer, 75 часов) урок: если единственный
сенсорный сигнал («пар») визуально неотличим от сигнала другого механизма
(«меха»), а игра нигде явно не разводит их — получается не «атмосферная
неопределённость», а тихо нечестная головоломка. **Правило для всех
разделов ниже**: там, где в UI вводится новый сенсорный сигнал, ЛИБО (а)
он однозначно отличим от всех остальных сигналов той же сцены, ЛИБО (б)
если он намеренно похож на другой (искажение специально путает два
сигнала) — это должно быть решением про Морок конкретно в этом месте, а
не случайной коллизией дизайнаUI, которую никто не заметил при разработке.

**0.3. Непрерывная формула, не бинарный рецепт — держать явно.**
(KCD2-ресёрч §6.3, главное предостережение всего документа.) Herbalist
принципиально **не имеет фиксированных рецептов** (`Alchemy.md`) —
Coherence непрерывна. Это структурно защищает от главного риска KCD2
(«один необъяснённый переключатель ломает всю партию»), но ТОЛЬКО если
UI не начнёт имитировать бинарные QTE-проверки поверх непрерывной формулы.
Правило: каждый раз, когда планируется новый интерактивный шаг варки
(порядок, тайминг, ручное действие) — проверять, остаётся ли его влияние
на результат непрерывным (небольшая ошибка → небольшое отклонение), не
скатывается ли он в скрытый pass/fail.

## 1. Инвентарь (трав/зелий/артефактов)

**Код сейчас:** `UInventoryWidget` (слоты, `VerticalBox`), `UItemTooltipWidget`.

**1.1. Убрать S_real из тултипа — самая срочная, самая дешёвая правка.**
`UItemTooltipWidget` сейчас показывает искажённое значение **и реальное
рядом в скобках** (`UI_Current.md`) — это прямое противоречие
`07_UX.md` («игрок никогда не получает доступ к системе напрямую»).
Действие: скобки с реальным значением убрать из релизного пути, оставить
только за отдельным дев-чит-флагом. Не исследовательская находка сама по
себе (найдено при чтении `UI_Current.md` для этого плана), но встаёт
первым пунктом именно потому, что дешевле и срочнее всего остального ниже.

**1.2. Физическая метафора — не буквальная калька примеров.**
(Диегетический ресёрч §1.1, §3.1.) Ни куртка Alone in the Dark, ни рюкзак
The Forest тематически не подходят травнице. Взять принцип («слоты
ограничены физическим объёмом объекта», не абстрактная сетка), не форму:
пестерь/сумка через плечо с отдельными мешочками-нычками по типу сырья.
Это скин поверх уже существующего `UInventoryWidget` (`VerticalBox`
слотов) — не переделка структуры данных, только визуальный слой.
Приоритет: ниже, чем 1.1 — контентная/арт задача, не срочный логический баг.

**1.3. Задел на `PerceiveClass`.** (Диегетический ресёрч §3.1, §3.4;
`DECISIONS_LOG.md` решение №2, уже отдельно отложено в `ROADMAP.md`.)
Когда/если `PerceiveClass` будет реализован — модель подмены брать по
Amnesia, не Eternal Darkness: подменяется само ПРЕДСТАВЛЕНИЕ (иконка+имя),
детерминированно от seed предмета (`PerceiveValue` уже даёт этот паттерн),
никогда не через фейковые «системные» сообщения (чужой жанр для фолк-хоррора).
Естественная точка первого столкновения игрока с этим — момент сбора
(см. §4), не инвентарь задним числом.

## 2. Варка зелья в котле

**Код сейчас:** `UAlchemyTransferWidget` (3 слота + вода + витрина
результата), `UAlchemySlotWidget`, `ComputeIntentCoherence` для превью.

**2.1. Локальный, не только глобальный сенсорный отклик.**
(Диегетический ресёрч §3.2; `DECISIONS_LOG.md` решение №6, уже
запланировано, но только для пост-процесса всего экрана.) Тот же параметр
(`CurrentGlobalDistortion` → `MPC_WorldStateFields`) должен управлять ещё и
локальными эффектами именно котла — ритм бульканья, цвет пара,
потрескивание углей — не только общей цветокоррекцией экрана. Даёт котлу
читаться как инструмент (в духе Iron Lung/SOMA), не просто как ещё один
объект под общим фильтром сцены.

**2.2. Порядок ингредиентов — уже рычаг формулы, сделать его видимым
UI-параметром.** (KCD2-ресёрч §6.1.) `ComputeIntentCoherence` уже
учитывает порядок закладки (`Coherence.md`) — совпадает с духом KCD2
(варка чувствительна к последовательности), просто без единственно
верного порядка. Когда `UAlchemyTransferWidget` получит диегетическую
переработку (не голые 3 слота) — порядок закладки должен быть управляемым
и заметным игроку действием, не скрытой деталью формулы, которую он
не может специально контролировать.

**2.3. Явный запрет на KCD2-стиль скрытого переключателя (см. §0.3).**
Конкретно: если варка получит ручной контроль темпа/огня — отклонение от
идеального темпа должно плавно сдвигать Coherence, а не переключать
скрытый bool «варка испорчена/не испорчена». Это прямое применение §0.3 к
самому рискованному по духу KCD2 разделу плана.

**2.4. Пауза без штрафа.** (KCD2-ресёрч §6.1, §4 — прямое улучшение KCD1→KCD2.)
Если варка обзаведётся тайминг-элементом (жар/кипение) — отвлечение
игрока (открыть Травник, свериться с записью) не должно механически
портить уже идущий процесс, если это не осознанное решение про конкретную
угрозу места (тот же принцип, что уже применён к Соловью-разбойнику —
разовая угроза при контакте, не фоновый штраф за паузу).

**2.5. Тиры результата по имени, не по числу — уже согласовано с
`Alchemy.md`.** (KCD2-ресёрч §6.2.) KCD2 подтверждает, что дискретные
именованные тиры (weak/regular/strong) читаются игроками понятно без
чисел. У Herbalist уже есть направление на именованные, не числовые
исходы (Bifurcation/Zaryana-ветки, `Alchemy.md`) — это не новое
заимствование, а подтверждение уже выбранного пути.

## 3. Травник (журнал)

**Код сейчас:** `UJournalLogWidget` (чистый C++, фильтр по ингредиенту),
`UJournalWidget`/`UJournalEntryRowWidget` (WBP, спроектированы, не
назначены — не блокирует).

**3.1. Модель Obra Dinn — уже одобрена в GDD, не полностью реализована в
поведении.** (Диегетический ресёрч §2, §3.3.) `07_UX.md §7.10` уже
формулирует «Травник фиксирует модель игрока, а не систему» — это
буквально модель судовой книги Return of the Obra Dinn: записи не
примиряются системой автоматически. Конкретное действие для
`JournalTypes.h`/`UJournalLogWidget`: два противоречащих наблюдения одного
и того же ингредиента (записанные при разном локальном Distortion) должны
остаться в списке РЯДОМ как есть, не заменяться и не усредняться —
замечать закономерность (папоротник при полной луне даёт больше Spirit) —
задача игрока, не подсказка экрана (это уже написано в `07_UX.md §7.2.4`,
пункт переносит формулировку в конкретное техническое требование).

**3.2. Голос персонажа, не нейтральный лог.** (Диегетический ресёрч §3.3.)
Текст записи — «мне показалось, что...», «горчит сильнее, чем в прошлый
раз», не нейтральное системное сообщение. Контентная задача (тексты
записей), не архитектурная.

## 4. Сбор ресурсов (харвест)

Уже безномерной по духу (`07_UX.md §7.2.3`). Единственная новая связка из
ресёрча: харвест — естественная ТОЧКА ПЕРВОГО СТОЛКНОВЕНИЯ с будущим
`PerceiveClass` (§1.3), не инвентарь постфактум — сорванное растение
может показаться не тем, чем окажется в Травнике позже. Отложено вместе с
самим `PerceiveClass` (`DECISIONS_LOG.md` №2), фиксируется здесь только
как заметка на будущее для того, кто будет реализовывать.

## 5. Диалоги с «хозяевами мест»

**Код сейчас:** `TalkTo`/`ChooseDialogueBranch`, текст от третьего лица
(`DT_Dialogue`).

Физические индикаторы (часы/RIG/трекер из диегетического ресёрча §1.3)
здесь неприменимы — нет приборов, только текст. Ближайшие рабочие аналоги
— Hellblade (ненадёжность через тон, не чекбоксы) и Darkest Dungeon
(ненадёжность через голос рассказчика, не цифры). Конкретное правило:
реплики, чувствительные к локальному Distortion, переписываются по ТОЙ ЖЕ
детерминированной seed-логике, что и `PerceiveValue` — не рандом при
каждом новом заходе в диалог (это был бы шум, не искажение восприятия
одного и того же состояния), а воспроизводимый сдвиг тона/отдельных слов
для того же состояния мира. Прямое продолжение `07_UX.md §7.7` («Morok не
обозначается напрямую») — никаких иконок/меток «этот диалог искажён».

## 6. Восприятие состояния клеток мира (оси Purity/Corruption/Distortion/Stability)

`07_UX.md §7.2.3` уже закрепляет словарь (рябь — Distortion, тёмные
прожилки — Corruption и т.д.) — не менять словарь. Добавить одно правило
из Eternal Darkness/Amnesia (диегетический ресёрч §3.6): при ОЧЕНЬ высоком
локальном Distortion разрешить визуальному тэгу одной оси на пару секунд
«одолжить» вид другой (клетка с низкой Stability может ненадолго показать
прожилки Corruption, которых у неё на самом деле нет) — не подмена данных,
подмена КОДА визуального прочтения, тот же уровень абстракции, где уже
работает `PerceiveValue`. Даёт ретроспективный told-you-so момент, прямое
продолжение `07_UX.md §7.8` («прогрессия — это снижение ошибки
интерпретации», не разблокировка нового UI).

## 7. Карта/навигация — открытый пробел

Ни `07_UX.md`, ни оба ресёрча впрямую не описывают систему карты для
Herbalist — её просто ещё нет в проекте ни в дизайне, ни в коде. Диегетический
ресёрч (§1.2) даёт два проверенных прецедента на будущее, если/когда карта
понадобится: Metro Exodus (бумажная карта, физически неполная, с
пометками) и Far Cry 2 (карта/компас в реальном времени, без полноэкранной
паузы). Не входит в объём этого плана как задача — фиксируется как
явный, не молчаливый пробел.

## 8. Порядок реализации (рекомендация)

Не жёсткий план спринтов — ориентир по риску/цене/зависимостям.

1. **§1.1 (убрать S_real из тултипа)** — дешевле и срочнее всего
   остального в этом документе, чистая правка существующего кода, без
   зависимостей.
2. **§3.1 (Травник не примиряет противоречия)** — тоже правка поведения
   уже существующего `UJournalLogWidget`/`JournalTypes.h`, не новый UI.
3. **§2.1 (локальный сенсорный отклик котла)** — расширяет уже
   запланированную (DECISIONS_LOG.md №6) механику, не с нуля.
4. **§1.2/§3.2 (арт/контент — сумка-травника, голос записей)** — по мере
   готовности контента, не блокирует остальное.
5. **§2.2-2.5, §6, §5** — ждут появления реального (не Exec-консольного)
   UI для соответствующих систем; сейчас в основном не с чем интегрировать
   технически, план фиксирует решения ЗАРАНЕЕ, чтобы будущий UI-проход не
   изобретал их на ходу.
6. **§4, §7** — зависят от ещё не принятых решений (`PerceiveClass`, карта)
   — не начинать раньше них.
