# Дорожная карта: что реально осталось

Обновлено 2026-08-30. Для истории того, что уже сделано, найдено и почему
решено именно так — `CHANGELOG.md`. Спутники: `AUDIT_AND_REFACTORING_PLAN.md`,
`DESIGN_World_State.md`, `META_AUDIT.md`.

**Ядро игры готово и работает**: пайплайн, биомный граф, восприятие,
сохранения, весь бестиарий (§16.2/§16.3/§16.4) с физическими акторами,
капища с типовыми бонусами, сутки/луна/сезоны, погода (собственный
C++-сигнал), сбор ингредиентов завязан на сезон/погоду/луну/HarvestStress,
Травник (читаемый лог с фильтром по ингредиенту), Заряна/Буян с презентацией,
единый `IInteractable`, заражение соседних клеток от испорченного полюса
(разрастание поганых мест по сетке, не только по биомному графу).
Всё — за автотестами (95/95 зелёных на 2026-08-30). Ниже — то, что осталось.

---

## Контент и ощущение игры (не код, либо контентная задача поверх готового C++)

- **Свой персонаж вместо шаблона** — `BP_FirstPersonCharacter` работает
  (движение уже через `AddMovementInput`/`AddYawInput`), но это редакторская
  задача на анимации/темп ходьбы/приседание, не C++.
- **HUD/меню** — паузы, выхода, отображения времени суток нет вовсе, хотя
  часы уже тикают (`GameClockSeconds`).
- **Звук** — только одно поле `HarvestSound`.
- **Локация Буяна** (живая/мёртвая вода) — флаг `bBuyanReached` и
  текстовое объявление готовы (`CheckBuyanCondition`,
  `UI/MemoryRevealWidget.h`), самой локации нет — level design, не код.
- **WBP/Input Action ассеты** — `JournalWidget`/`JournalEntryRowWidget`
  (богатая раскладка с полем на каждую ось) и их Input Action (`JournalAction`)
  не назначены в редакторе. Не блокирует: `JournalLogWidget` (C++-без-WBP)
  уже работает через `ToggleJournalUI()`/Exec без них — заводить WBP имеет
  смысл только если понадобится более богатый экран, чем читаемый лог.

## Механики с открытым дизайном

- **Реальный Ultra Dynamic Weather** — сейчас используется placeholder
  C++-сигнал (`GetWindIntensity`/`GetSnowIntensity`/`IsWindy`/`IsBlizzard`/
  `GetRainIntensity`/`IsRainy`, детерминированная value-noise). Плагин
  физически не установлен в проект. Точка подмены задокументирована
  (`15_Cycles_And_Shrines.md §15.7`) — заменить тела функций, вызывающий код
  и `bRequiresWeather`/`bRequiresDryWeather` не трогать.
- **"Хозяин" растений и ритуал сбора** (Леший/Водяной/Русалки/Хозяин
  Севера...) — почти в каждой карточке компендиума назван, но сознательно
  отложено прямым выбором пользователя 2026-08-29: данных много, часть
  карточек противоречит друг другу (Ольха речной поймы — правило "сухое/
  живое дерево" наоборот, чем у остальных деревьев), и это разошлось бы с
  уже принятым решением, что `Landmark.Respect` меняется только через явное
  подношение (Apply), не автоматически от сбора. Естественная форма без
  нового канала записи, если возьмёмся: читать существующий `Respect` как
  ещё один множитель `Suitability` в `GetRandomResourceForBiome`, не писать
  в него при сборе.
- **`PerceiveClass`** — сейчас искажаются только числа состояния, не сам
  факт "что это за вещь"; перепутать один ингредиент с похожим нельзя.
  06_Progression подразумевает и такое искажение.
- **История/Coherence в метрике мира** — `Distance_итог = Distance ×
  (2 − AverageCoherence)` описана в `15_Cycles_And_Shrines.md §15.5.1`, не
  реализована в коде (сейчас читается голый `Distance`).
- **PCG/материалы** — задел есть (`MPC_WorldStateFields.uasset`), визуальный
  вывод состояния мира в материалы не продолжен.

## Архитектурный долг

**✅ Закрыто 2026-08-30 (два из трёх пунктов).** `FCommandGraph`
переименован в `FCommandBatch` (честное имя — плоский `TArray`, не граф
зависимостей; ни одна из шести команд не зависит от другой в пределах
тика, строить настоящий граф было бы решением несуществующей задачи),
`Talk`/`FTalkCommand`/мёртвый `ExecutionOrder` удалены целиком — не
доведены до реализации, а убраны: `Talk` не имел ни одного вызывающего
пути, и `17_Hero_And_Community.md` прямо отвергает диалог как механику.
Резолв имени/perceived-состояния по виджетам — перепроверено, уже
централизовано (`GetItemDisplayName`, `HerbalistNameUtils.h`), все
проверенные виджеты идут через него, отдельного долга не было. Подробности
— `CHANGELOG.md`, `DESIGN_World_State.md §23`.

- **Полный переход Morok/Zaryana на read-time оверлей** — осознанно
  отложенное архитектурное решение (не баг): тактический фикс (сравнение
  "изменилось ли значение" перед записью в `TargetStateNudges`) уже закрыл
  измеренную проблему (400/400 клеток грязнились от нулевых полей).
  Полная миграция потребовала бы сперва завести сохранение для
  `BiomeGraphSubsystem::Nodes` (сейчас нигде не сохраняется) и тронула бы
  общий цикл релаксации, которым пользуются бистабильность/капища/
  Гнильники/Берегиня — непропорциональный blast radius. Подробности —
  `AUDIT_AND_REFACTORING_PLAN.md §7.1/§7.3`.

## Бестиарий, необязательные хвосты

Основной корпус (§16.2/§16.3/§16.4) закрыт полностью. Два пункта оставлены
как есть осознанно, не как недоделка:
- §16.5 (Вурдалаки/Навьи/Оборотни/Лихоманки/Черти) — общий разлитый ночной
  нудж уже реализован, индивидуальных карточек для них не заводилось: они
  не претендуют на клетку по спецификации, отдельные записи не добавили бы
  наблюдаемого поведения.
- Морочники — не отдельная сущность, а имя для уже реализованного
  `PerceiveValue()`.

## Известный пробел в тестировании

Headless UI-тестирование виджетов не настроено — все правки UI этой сессии
(Травник, Инвентарь, Заряна) проверены сборкой + автотестами на логике, но
не интерактивно через PIE. Не блокирует, но при следующей UI-правке стоит
иметь в виду.
