# Как проверить игровую систему в движке

Пошаговый гайд. Долгоживущий: описывает **порядок и метод**, а не разовый
список правок конкретной сессии — для этого есть `PIE_VERIFICATION_PLAN.md`
(чек-лист сессии 2026-09-03, наполовину закрытый, историческая справка).

Все команды проверены 2026-09-07 на UE 5.7. Пути жёсткие под эту машину:
движок `G:\UE_5.7`, проект `G:\herbalist\ProjectHerbalist`.

---

## Принцип: пять уровней, снизу вверх

Каждый следующий уровень дороже предыдущего и ловит то, чего предыдущий не
видит. Порядок не произвольный — он выведен из реальных промахов, а не из
удобства:

| Уровень | Стоимость | Что ловит | Чего НЕ ловит |
|---|---|---|---|
| 1. Сборка + автотесты | ~2 мин | Логика в изоляции, регрессии | Всё, что зависит от данных ассетов и живого мира |
| 2. Данные без запуска | ~1 мин | Расхождение ассетов с документацией | Поведение |
| 3. Headless `-game` | ~1 мин | Мир вообще собирается: биомы, посев, покрытие | Ввод, UI, длительные процессы |
| 4. PIE вручную | 10–30 мин | Базовый цикл глазами игрока | Медленные процессы (порча, зарастание) |
| 5. Долгий прогон | 30+ мин | Устойчивость математики во времени | — |

**Главное, чему научила практика: уровень 1 систематически лжёт о мире.**
До 2026-09-07 весь набор тестов молча считал математику на **нулевых
дефолтах биомов** — `DT_BiomeDefaults` подключал только
`GameMode::BeginPlay`, которого в editor-мире автотеста нет. Тесты были
зелёными и проверяли не то. Трижды за одну сессию баг мировой симуляции
находился реальным прогоном, а не тестами. Поэтому уровни 3–5 не
«необязательное дополнение», а обязательная часть проверки.

## Уровень 1 — сборка и автотесты

### 1.1 Собрать

```bash
"G:/UE_5.7/Engine/Build/BatchFiles/Build.bat" ProjectHerbalistEditor Win64 Development "G:\herbalist\ProjectHerbalist\ProjectHerbalist.uproject" -WaitMutex
```

Ожидается `Result: Succeeded`.

Если `LNK1104 ... UnrealEditor-ProjectHerbalistTests.dll` — **открыт редактор
или висит коммандлет**, они держат DLL. Закрыть редактор; зависший
коммандлет снять:

```bash
taskkill //F //IM UnrealEditor-Cmd.exe
```

### 1.2 Прогнать тесты — обязательно ДВАЖДЫ

```bash
"G:/UE_5.7/Engine/Binaries/Win64/UnrealEditor-Cmd.exe" "G:\herbalist\ProjectHerbalist\ProjectHerbalist.uproject" -ExecCmds="Automation RunTests Herbalist; Quit" -unattended -nopause -nosplash -NullRHI -log
```

Подсчёт результата:

```bash
L=G:/herbalist/ProjectHerbalist/Saved/Logs/ProjectHerbalist.log; echo "OK: $(grep -c 'Result={Success}' "$L")  Fail: $(grep -c 'Result={Fail}' "$L")"; grep "Result={Fail}" "$L" | sed 's/.*Path={/  /;s/}$//'
```

Эталон на 2026-09-07: **472 / 0**.

Два прогона нужны не для перестраховки: тесты идут в одном персистентном
editor-мире и делят глобальное состояние (CDO настроек, статическая таблица
биомов, акторы прошлых тестов). Тест, забывший вернуть глобальную настройку,
проходит сам и роняет следующий — это ловилось в проекте не раз. Разный
результат двух прогонов = зависимость от порядка, а не «флаки».

Подмножество по имени:

```bash
-ExecCmds="Automation RunTests Herbalist.BiomeGraph; Quit"
```

## Уровень 2 — данные без запуска

Проверяет то, чего не видит ни один тест логики: **совпадают ли игровые
ассеты с документацией**. 2026-09-07 здесь нашлось 35 расхождений из 112 —
у Болота в строке суши стояли числа его водного состояния, а
`StressRecoveryMultiplier` был нейтральной единицей у всех восьми биомов,
то есть механика зарастания была реализована и выключена одновременно.

### 2.1 Сверка дефолтов биомов с компендиумом

```bash
"G:/UE_5.7/Engine/Binaries/Win64/UnrealEditor-Cmd.exe" "G:\herbalist\ProjectHerbalist\ProjectHerbalist.uproject" -run=BiomeDefaultsSync
```

Идемпотентен. Ожидается `приведено к документации значений: 0` и восемь
строк `= <Биом>: уже по документации`. Любая строка `~ Биом.Поле: X -> Y`
означает, что ассет уехал от карточек — и коммандлет это уже исправил.

Это же закрыто автотестом `BiomeDefaults.AssetMatchesTheCompendium`, так что
на уровне 1 расхождение тоже упадёт. Коммандлет нужен, чтобы **починить**.

### 2.2 Выгрузить настоящее содержимое таблиц

Когда нужно глазами сравнить ассет с `herbalist_docs/CSV_tabs/*.json`:

```bash
"G:/UE_5.7/Engine/Binaries/Win64/UnrealEditor-Cmd.exe" "G:\herbalist\ProjectHerbalist\ProjectHerbalist.uproject" -run=DataTableExport -out=C:/temp/actual
```

Кладёт `<Имя>.actual.json` по файлу на таблицу. **Не пишет поверх
`CSV_tabs/`** — те считаются отражением документации, затирать их
содержимым ассета нельзя.

Порядок правды: **документация → json → ассет**. Расходятся — прав документ.

### 2.3 Состояние тестовой карты, не трогая её

```bash
"G:/UE_5.7/Engine/Binaries/Win64/UnrealEditor-Cmd.exe" "G:\herbalist\ProjectHerbalist\ProjectHerbalist.uproject" -run=PlaytestMapResize -dryrun
```

Печатает сетку, `CellSize` в метрах, размах мира и число биом-регионов,
ничего не записывая. Эталон: `250x250, CellSize=100 (клетка 1.00 м), мир
250 м, биом-регионов 8`.

Полный список коммандлетов — `TOOLS_REFERENCE.md`.

## Уровень 3 — headless `-game`

Самая выгодная проверка на минуту времени: собирается ли мир целиком —
биомы, ландшафт, посев хозяев мест, якорей, курганов и POI. Ловит то, что
тесты пропускают по построению, потому что тесты работают в маленьком
editor-мире без настоящей карты.

```bash
MSYS_NO_PATHCONV=1 "G:/UE_5.7/Engine/Binaries/Win64/UnrealEditor-Cmd.exe" "G:\herbalist\ProjectHerbalist\ProjectHerbalist.uproject" /Game/Maps/L_Playtest -game -unattended -nosplash -NullRHI -ExecCmds="quit" -log
```

> `MSYS_NO_PATHCONV=1` обязателен. Без него Git Bash превращает
> `/Game/Maps/L_Playtest` в `C:/Program Files/Git/Game/Maps/L_Playtest`,
> карта молча не грузится, а процесс падает с `EXCEPTION_ACCESS_VIOLATION`
> на выходе. Падение при этом — следствие, а не причина; смотреть надо на
> строку `LoadMap`.

Разбор:

```bash
L=G:/herbalist/ProjectHerbalist/Saved/Logs/ProjectHerbalist.log
grep -a "LoadMap:" "$L" | head -1
grep -a "вне всех ABiomeRegionVolume" "$L"
grep -ac "Seeded landmark" "$L"
grep -a "Cached .* cell heights" "$L"
```

Что должно быть:

| Проверка | Эталон | О чём говорит отклонение |
|---|---|---|
| `LoadMap:` | `/Game/Maps/L_Playtest` | иначе путь исказился, всё остальное бессмысленно |
| «вне всех ABiomeRegionVolume» | строк **нет** | биом-полосы не покрывают сетку: ресурсов и хозяев мест не будет |
| `Seeded landmark` | **13** | 0 — следствие непокрытия выше |
| `Seeded legendary anchor` | **16** | то же |
| `Cached N cell heights` | 62 500 (при 250×250) | 0 — ландшафт не найден или не покрывает сетку |
| код возврата | 0 | ненулевой при верном `LoadMap` — настоящий сбой |

**Проверка разброса** — якоря не должны жаться к одному краю:

```bash
grep -a "Seeded landmark\|Seeded legendary" "$L" | grep -oE "\([0-9]+," | sort -u | head
```

X должен идти по всей ширине. Если все при X = 0…3 — вернулась регрессия
посева «первая подходящая клетка».

**Если покрытие сломано** (сетку меняли руками в редакторе, регионы
отстали):

```bash
"G:/UE_5.7/Engine/Binaries/Win64/UnrealEditor-Cmd.exe" "G:\herbalist\ProjectHerbalist\ProjectHerbalist.uproject" -run=PlaytestMapResize
```

Без `-size` размер сетки сохраняется, перекладываются только полосы.
**Редактор должен быть закрыт**, иначе несохранённые правки конфликтуют.
Ландшафт коммандлет не трогает — его тянуть в редакторе.

## Уровень 4 — PIE вручную

Только здесь проверяются ввод, UI и то, как всё ощущается.

### 4.1 Перед запуском

- Открыть `/Game/Maps/L_Playtest`.
- Убедиться, что правки сетки **сохранены**: PIE копирует мир из редактора
  вместе с несохранёнными изменениями, а коммандлеты работают с диском. Это
  расхождение уже один раз стоило часа разбора — в PIE шло 500×500, на диске
  лежало 250×250.

### 4.2 Стартовые строки лога — читать всегда

При каждом запуске PIE в логе появляется паспорт мира:

```
LogHerbalistWorld: Landscape found: Landscape_0
LogHerbalistWorld: Cached 62500 cell heights from landscape
LogHerbalistWorld: [Entities] Seeded landmark ... (13 строк)
LogHerbalistWorld: [Entities] Seeded legendary anchor ... (16 строк)
LogHerbalistWorld: [Kurgan] Seeded ... (2 строки)
LogHerbalistWorld: [POI] Seeded: Totem(...) Svetloyar(...) GoryuchKamen(...) Solovey(...) KalinovMost(...)
LogHerbalistData: IngredientRegistrySubsystem loaded 103 ingredients
LogHerbalistBiome: Initialized with 8 nodes, 14 edges
LogHerbalist: Biome table initialized successfully.
```

Тревожные строки:

- `AlchemyTableActor ... is outside the grid — Домовой/Роса не зарегистрированы`
  — стол вне сетки, вся ветка Домового и Росы мертва.
- `Ввод: ... не назначен в Blueprint'е контроллера` — клавиша не работает
  (известны `JournalAction`, `UsePotionAction`, они в `ROADMAP.md`).
- `InitializeCells: N/M клеток (X%) вне всех ABiomeRegionVolume` — см.
  уровень 3.

### 4.3 Базовый цикл

Проверять в этом порядке, каждый шаг оставляет след в логе:

1. **Сбор.** Подойти к растению, собрать. Ожидается
   `Сбор: <id> -- команда отправлена в пайплайн`. Строка
   `подойди ближе, предел 200 см` — не баг: `MaxHarvestDistance` это
   дистанция от персонажа, надо подойти.
2. **Инвентарь** — `ShowInventory`. Предмет на месте, состояние в [0,1].
3. **Варка** у алхимического стола: два ингредиента + вода. Ожидается
   фольклорное имя зелья.
4. **Применение** зелья к клетке — `TestNewApply`. В логе
   `ApplyStateDelta: received N biome activations`.
5. **Сохранение и загрузка** — `SaveGame`, затем `LoadGame`. Инвентарь и
   состояние мира совпадают.

Полный список консольных команд — 45 штук в
`Player/HerbalistPlayerController.h` (`UFUNCTION(Exec)`), от `HarvestHere` и
`ReportGridCorruption` до `PayKalinovMostToll`.

### 4.4 Диагностика мира в любой момент

```
ReportGridCorruption
```

Плюс автоснимок раз в 30 с (`GridCorruptionReportIntervalSeconds`) —
специально, чтобы не нужно было ничего нажимать во время долгой сессии.

### 4.5 Карта состояния мира — живая ли она

Проверка появилась 2026-09-08, когда отклик растительности на порчу
заработал целиком. Автотестами она не заменяется в принципе: выгрузка на
GPU в headless-прогоне не выполняется (RHI нет), а «правильно ли выглядит»
не проверяется вообще ничем, кроме глаз.

Проверять надо **в этом порядке** — каждый шаг опирается на предыдущий, и
пропустив первый, второй будешь отлаживать вслепую.

**Шаг 1. Текстура вообще заполняется.** Запустить PIE на пару секунд,
остановить, открыть `RT_WorldStateMap` в Content Browser.

- Чёрная — выгрузка не доезжает. Дальше идти бессмысленно.
- Тёмно-оливковая — это настоящие данные: R (Distortion) и G (Corruption)
  у нетронутого мира лежат в 0.25…0.70, B (вытоптанность) в нуле.

Однотонность — **не** признак поломки. Она означает ровно то, что на карте
один биом: у `L_TestDev` единственный `BiomeRegionVolume` (Болото). Полосы
восьми биомов — это `L_Playtest`, но там нет PCG и травы.

**Шаг 2. Текстура СЛЕДУЕТ за симуляцией.** Первый шаг доказывает только,
что она заполнена; статический узор мог бы взяться откуда угодно. Нужно
что-то сделать и увидеть последствие:

- собрать ресурсы несколько раз в одном месте;
- открыть `RT_WorldStateMap` и посмотреть **синий канал** (в просмотрщике
  render target каналы переключаются).

До сборов он в нуле по всей карте, после — в этом месте проступает пятно
(`HarvestStress`). Материал для этой проверки трогать не нужно: B никуда
не заведён, и именно поэтому пятно доказывает канал данных, а не материал.

**Шаг 3. Скачки сглажены.** Применить зелье на клетку. Цвет травы обязан
поехать **постепенно**, а не перекраситься мгновенно: симуляция меняет
клетку скачком, но картинка догоняет её со скоростью
`WorldStateMapVisualRatePerSecond` (0.01 ед/с — предел собственного дрейфа
мира). Полный размах оси занимает 100 секунд, около полутора игровых часов
при `GameDayMinutes = 32`. Мгновенная перекраска означает, что сглаживание
выключено или обойдено.

## Уровень 5 — долгий прогон

Единственный способ поймать медленные ошибки мировой симуляции: рост порчи,
несходящиеся контуры, дрейф. Именно так были найдены три бага биом-графа,
которые не видел ни один тест.

**Метод:** запустить PIE, сделать 2–3 сбора, оставить игру идти 30–60 минут,
затем сравнить снимки `Grid corruption (auto)` в начале и в конце.

Здоровый мир (эталон 2026-09-07, карта 250×250):

```
Grid corruption (auto): 62500 cells, 0 degrading (0.0%), Distortion avg=0.383 min=0.250 max=0.700
```

Как читать:

- **`avg` не должен ползти.** Медленный рост во всех снимках подряд —
  контур с положительной обратной связью, самый дорогой класс ошибок в
  проекте. `avg ≈ 0.38` — это среднее по документированным дефолтам.
- **`min = 0.250`** — природный Distortion Тайги, самого чистого биома.
  Ниже — что-то тянет мир вниз; биом не может уйти ниже собственной природы
  без вмешательства игрока (зафиксированный инвариант).
- **`max = 0.700`** — Болото. `max = 1.000` нормально **только** если
  `degrading > 0`: это бистабильный испорченный полюс на клетках, где
  собирали. Без единой degrading-клетки `max = 1.0` — ошибка.
- **`degrading`** растёт только от действий игрока. Самопроизвольный рост —
  заражение вышло из-под контроля.

Формулы, точки равновесия и все константы — `MATH_REFERENCE.md`.

## Как читать логи

**Где:** `ProjectHerbalist/Saved/Logs/ProjectHerbalist.log` — всегда
последний запуск.

**Ротация — главная ловушка.** Каждый новый запуск (включая прогон тестов!)
перезаписывает `ProjectHerbalist.log`, а предыдущий уезжает в
`ProjectHerbalist-backup-<дата>.log`. Разбирая PIE-сессию, **сначала
скопируйте лог**, иначе следующий же прогон тестов его затрёт:

```bash
ls -lat G:/herbalist/ProjectHerbalist/Saved/Logs/*.log | head -5
```

**Кодировка.** Файл в UTF-8, но консоль Windows его коверкает. Кириллицу
читать через файл, а не через терминал:

```bash
export PYTHONIOENCODING=utf-8
```

либо перенаправлять вывод в файл и открывать его.

**Полезные фильтры:**

```bash
L=G:/herbalist/ProjectHerbalist/Saved/Logs/ProjectHerbalist.log
grep -a "LogHerbalist" "$L" | sed 's/^\[[^]]*\]\[[^]]*\]//'   # только свои каналы
grep -a ": Error:" "$L"                                        # ошибки
grep -a "Grid corruption" "$L"                                 # снимки состояния мира
grep -ac "Bringing World" "$L"                                 # сколько было запусков PIE
```

Каналы: `LogHerbalistWorld`, `LogHerbalistPlayer`, `LogHerbalistAlchemy`,
`LogHerbalistBiome`, `LogHerbalistData`, `LogHerbalistZaryana`,
`LogHerbalist`.

## Ловушки, каждая стоила времени

1. **Тесты идут не на тех данных.** Исторически — на нулевых дефолтах
   биомов. Сейчас закрыто (`FBiomeDefaults` грузит таблицу лениво сам), но
   принцип остаётся: зелёный тест не доказывает, что мир правильный.
2. **Конфиг перекрывает дефолт в заголовке.** `UHerbalistSettings` помечен
   `UCLASS(config = Game, defaultconfig)` — действует
   `Config/DefaultGame.ini`, а не значение в `.h`. Я на этом ошибся,
   заявив, что стриминг выключен: в заголовке `-1`, в ini `100`.
   **Действующие значения смотреть в ini или в рантайме, не в заголовке.**
3. **Редактор ≠ диск.** PIE берёт мир из редактора вместе с
   несохранёнными правками; коммандлеты — с диска.
4. **Git Bash коверкает пути `/Game/...`** — `MSYS_NO_PATHCONV=1`.
5. **Редактор держит DLL** — сборка падает с LNK1104.
6. **Абсолютные константы против долей от `CellSize`.** `CellSize` в
   сантиметрах: дев 100 (клетка 1 м), боевой 1000 (клетка 10 м, мир 5×5 км).
   Величины, заданные долей от клетки, при смене масштаба меняются, а
   абсолютные — нет. Не всякая обязана масштабироваться: дистанция сбора —
   свойство персонажа и от размера клетки не зависит.
7. **`Absolute World Position` — это LWC.** Маскировать его до двух
   компонент ПЕРЕД арифметикой нельзя: получается `FWSVector2`, для
   которого операции не определены («Invalid input types: FWSVector2,
   FWSVector2»). **Вычитать в трёх компонентах, маскировать после.**
   Параметр коллекции при этом приходит как float4 — его тоже надо
   маскировать, иначе «Arithmetic between types LWCVector2 and float4 are
   undefined». Стоило отдельного круга правок 2026-09-08.
8. **У render target два независимых признака гаммы, и они расходятся.**
   Ресурс на GPU создаётся из `IsSRGB()`, а редактор материалов сверяет тип
   сэмплера с унаследованным полем `UTexture::SRGB` — и оно
   синхронизируется ТОЛЬКО внутри `PostEditChangeProperty`. Ассет,
   созданный коммандлетом через `NewObject`, этого события не видит
   никогда: сэмплирование линейное, а поле заявляет sRGB, и материал не
   компилируется («Sampler type is Linear Color, should be Color»). Движок
   сам признаёт расхождение комментарием у `IsSRGB()`. Чинится
   `-run=WorldStateMapSetup` (он теперь правит флаг и на существующих
   ассетах) или вручную: сменить Render Target Format туда-обратно.

---

## Что делать при находке

1. **Замерить, не гадать.** Догадка о причине проверяется числом из лога.
   За одну сессию три моих правдоподобных гипотезы были опровергнуты
   замером — включая ту, где правка выглядела верной, собиралась и не
   работала.
2. **Найти корень, а не симптом.** Пример: биом-регионы отстали от сетки —
   чинится раскладкой полос, а не подгонкой посева.
3. **Написать тест на НАБЛЮДАЕМОЕ свойство**, а не на использование
   механизма. «Использует RNG» проходит и на сломанном коде; «максимальный
   X больше третьей колонки» — нет.
4. **Перепроверить тем же уровнем, на котором нашли.** Найдено реальным
   прогоном — проверять реальным прогоном, а не только тестом.
5. Записать в `CHANGELOG.md` (в конец, с обоснованием), открытое — в
   `ROADMAP.md`.
