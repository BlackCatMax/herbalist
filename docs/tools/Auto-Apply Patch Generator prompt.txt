```
🔧 PROMPT: Auto-Apply Patch Generator (GDD Sync) — v2

Ты получил список исправлений (FIX blocks) для документов:

- technical.md
- design.md
- glossary.md

Твоя задача — преобразовать их в ГОТОВЫЕ PATCH-ИЗМЕНЕНИЯ,
которые можно применить напрямую через git apply.

---

# ОСНОВНЫЕ ПРАВИЛА

- НИКАКИХ объяснений
- НИКАКИХ комментариев вне патчей
- ТОЛЬКО изменения
- НИКАКИХ пересозданий файлов целиком

---

# ФОРМАТ ВЫВОДА

Используй unified diff формат.

Каждый файл — отдельный PATCH-блок:

--- a/<file>
+++ b/<file>
@@
<контекст>
- старый текст
+ новый текст
<контекст>

---

# ТРЕБОВАНИЯ К PATCH

## 1. Точечность

- Изменять ТОЛЬКО строки, указанные в FIX
- НЕ трогать остальной текст
- НЕ переформатировать документ
- НЕ изменять порядок разделов

---

## 2. Контекст

- Добавлять 2–5 строк контекста ДО и ПОСЛЕ изменения
- Контекст должен существовать в файле
- Контекст НЕ считается изменением

Ограничение:
- 1–3 строки изменений (строки с "-" и "+")
- контекстные строки в это ограничение НЕ входят

---

## 3. Строгое совпадение

Старый текст обязан:

- совпадать с файлом СИМВОЛ-В-СИМВОЛ
- включать полный изменяемый фрагмент строки

Запрещено:

- частичное совпадение
- "похожие" строки
- fuzzy matching

Если точное совпадение невозможно:

[MANUAL REQUIRED]

file: <file>

reason:
невозможно точно найти строку

expected change:
<что должно быть изменено>

---

## 4. Соответствие FIX

Каждый PATCH:

- соответствует РОВНО одному FIX

Запрещено:

- объединять разные FIX в один PATCH

Исключение:

- если несколько FIX изменяют одну и ту же строку
→ объединить их в один PATCH
ИЛИ выдать:

[CONFLICT]

---

## 5. Стабильность

- НЕ удалять текст без явного указания
- НЕ добавлять новые сущности, если это не указано в FIX
- НЕ изменять структуру документа

---

## 6. Повторные изменения

- одна и та же строка может изменяться ТОЛЬКО один раз
- если требуется несколько изменений → объединить в один PATCH

---

## 7. Порядок PATCH

- PATCH-блоки должны идти в порядке появления в файле (сверху вниз)
- не создавать перекрывающихся изменений

---

# СПЕЦИАЛЬНЫЕ СЛУЧАИ

## Формулы

- заменить ТОЛЬКО формулу
- сохранить весь окружающий текст

---

## Glossary

- заменить ТОЛЬКО определение
- НЕ менять формат списка

---

## Пайплайн

- заменить ТОЛЬКО конкретные шаги или порядок
- НЕ переписывать весь раздел

---

# ЖЁСТКИЕ ТРЕБОВАНИЯ К DIFF

Каждое изменение ОБЯЗАНО использовать:

- старый текст
+ новый текст

---

Контекст:

- 2–5 строк до и после
- реальные строки из файла
- без абстрактных описаний

---

Запрещено:

- переписывать абзацы целиком
- изменять более 1–3 строк за PATCH
- изменять текст вне FIX

---

# КОНФЛИКТЫ

Перед выводом:

- проверить, не изменяется ли один и тот же участок дважды

Если да:

[CONFLICT]

---

# ЦЕЛЬ

Выдать набор PATCH-блоков,
которые:

- применяются через git apply без ошибок
- не требуют ручного редактирования
- сохраняют полную согласованность системы
```
