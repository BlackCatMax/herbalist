# Промпты на обновление документации

Готовые задания для агента (Claude Code в этом репозитории). Копировать блок
целиком, подставить `<...>`. Общие правила ниже вшиты в каждый промпт — их
не надо повторять отдельно.

## Общие правила (входят в каждый промпт)

```text
Проект Herbalist, UE 5.7, репозиторий G:\herbalist, язык документации и
общения — русский.

Порядок правды:
- механика и числа игры — канон `herbalist_docs/Herbalist_Vault/02_GDD`,
  глоссарий `01_Glossary`, карточки `04_Compendium`;
- данные: документация → `herbalist_docs/CSV_tabs/*.json` → ассет;
- как устроено сейчас — код (`ProjectHerbalist/Source`), его отражение —
  `03_Technical/Current`;
- `docs/design/DESIGN_*.md` — черновики, не канон;
- `CHANGELOG.md` — летопись, только дописывается в конец, прошлое не
  правится; `ROADMAP.md` — только открытое;
- `03_Technical/Archive`, `docs/audits` — история, ссылки на удалённое там
  законны, не «чинить».

Нельзя:
- выдумывать лор, числа, имена, решения. Где документ противоречит коду и
  непонятно, что верно, — не правь, а вынеси в список вопросов;
- откатывать или переписывать чужой текст сверх нужного для правки;
- удалять файл, не проверив входящие ссылки (`grep` по репозиторию);
- пушить.

Порядок работы:
1. `py tools/docs_audit/audit_docs.py` — снять исходные числа.
2. Разобрать находки по `docs/maintenance/DOCS_AUDIT_CHECKLIST.md`:
   механические (ссылки, опечатки, форма фронтматтера, индексы) — править;
   смысловые — сверить с кодом/каноном и править только однозначное.
3. Повторный прогон: ошибок 0, предупреждений не больше исходного.
4. Если трогал код или ассеты — сборка и два прогона автотестов
   (`docs/verification/ENGINE_VERIFICATION_GUIDE.md`, уровень 1).
5. Коммит на логическую единицу с явными путями (`git commit -- <пути>`);
   запись в CHANGELOG — если менялся смысл.
6. Отчёт: что поправлено (числа скрипта до/после), что не тронуто и почему,
   список вопросов к автору.
```

## 1. Периодический проход

```text
<общие правила>

Задача: периодическая проверка документации по
docs/maintenance/DOCS_AUDIT_CHECKLIST.md — шаг 1 (скрипт) и шаг 2 (ручная
часть, все разделы). Механические находки исправить, смысловые — исправить
однозначные, остальные — вопросами. Легаси, найденное C11 и ручной частью,
удалить или перенести в архив, проверив ссылки.
```

## 2. Документация после изменения кода

```text
<общие правила>

Задача: привести документацию в соответствие с изменениями кода с коммита
<хэш или дата> по HEAD.

1. `git log --stat <хэш>..HEAD` и записи CHANGELOG за этот период — что
   поменялось в механике, данных, командах, сейве, инструментах.
2. Для каждого изменения найти, где оно описано: главы GDD, глоссарий,
   карточки, 03_Technical/Current, MATH_REFERENCE, TOOLS_REFERENCE,
   docs/verification (команды, эталоны, паспорт мира), DESIGN_* (помечено ли
   «реализовано»).
3. Обновить описание; новое Exec- или консольную команду, коммандлет, скрипт —
   внести в соответствующий гайд/справочник (проверка C12 это подтвердит).
4. Прогон скрипта до и после.
```

## 3. Чистка легаси

```text
<общие правила>

Задача: убрать легаси из документации.

Легаси — это:
- резервные копии и разовые отчёты скриптов в хранилище;
- одноразовые скрипты, которые уже отработали и нигде не описаны;
- документы `status: superseded`/`archived` вне `03_Technical/Archive`;
- реализованные спецификации в `03_Technical/Future` (перенести в Current);
- упоминания удалённых типов, файлов, тестов, команд в каноне и
  инженерных документах (C09, C10);
- зачёркнутые пункты ROADMAP (их история уже в CHANGELOG);
- эталоны и описания, противоречащие текущему коду (карта, размер сетки,
  число тестов, клавиши, команды).

Для каждого кандидата: входящие ссылки → решение (удалить / в архив с
плашкой «АРХИВ» / исправить) → правка ссылок. Список удалённого с
причиной — в отчёт и в сообщение коммита.
```

## 4. Карточки компендиума

```text
<общие правила>

Задача: сверить карточки <категория или «все»> с данными и между собой.

1. `py tools/docs_audit/audit_docs.py --only C02,C03,C04,C05,C06,C14`.
2. Для чисел: `-run=BiomeDefaultsSync` (биомы) и `-run=DataTableExport`
   (остальные таблицы) — сравнить ассет с карточкой и `CSV_tabs`; правда —
   карточка, если только она не противоречит собственному тексту.
3. Текст против чисел: «ядовитое» при низкой Corruption, «чистое» при
   высоком Distortion — в вопросы, не править самому.
4. Отчёт: расхождения ассет/json/карточка с направлением правки.
```

## 5. Гайды проверки в движке

```text
<общие правила>

Задача: обновить docs/verification под текущее состояние.

1. Уровни 1 и 3 из ENGINE_VERIFICATION_GUIDE.md выполнить по-настоящему и
   переписать эталоны из свежего лога: число тестов, строки паспорта мира,
   карта по умолчанию (`ProjectHerbalist/Config/DefaultEngine.ini`).
2. `py tools/docs_audit/audit_docs.py --only C12,C13` — каждая
   неописанная команда получает строку в разделе docs/verification/pie по
   своей системе: зачем, пример вызова, что ждать в логе.
3. Ничего не описывать по памяти: строка лога — только скопированная из кода
   (`UE_LOG`) или из настоящего прогона.
```
