# Проверка документации: чек-лист

Периодический проход по всей документации: хранилище (GDD, глоссарий,
компендиум, техснимки), инженерные документы в `docs/`, `ROADMAP.md`.
Автоматическая часть — скрипт, ручная — то, что скрипт не видит в
принципе: смысл, противоречия, лор. Правка найденного — промпт
`DOCS_UPDATE_PROMPT.md` рядом.

## Когда прогонять

- после этапа работы, закрывшего пункт ROADMAP;
- после добавления команды, коммандлета, скрипта, карточки, главы GDD;
- раз в две недели, даже если «ничего не менялось» — дрейф копится молча;
- перед тем как отдавать документацию во внешний проход (Cowork, ревью).

## Шаг 1. Скрипт — 1 минута

```bash
py tools/docs_audit/audit_docs.py
```

Отчёт — `build/docs_audit/report.md` (в git не попадает). Код выхода 1 —
есть ошибки. В Claude Code то же быстрее — скилл `/docs-audit` (аргументы
`quick`, `full`, `fix`, `strict` или список проверок, например `C06,C09`;
`.claude/skills/docs-audit/SKILL.md`, там же текущий эталон находок). Прогон отдельных проверок: `--only C06,C09`; список —
`--list`. Тесты самого скрипта:

```bash
py -m unittest tools/docs_audit/test_audit_docs.py
```

| Проверка | Что ловит | Что делать |
|---|---|---|
| C01 фронтматтер | нет `---`-шапки в глоссарии, GDD, компендиуме; YAML не разбирается | добавить шапку по шаблону `00_Meta/Templates` |
| C02 поля карточек | нет обязательного ключа; число вне [0, 1]; `d_base`/`d_manifest` не из 4 чисел; `level`/`behavior`/`danger` не из принятых значений | исправить карточку; новое значение перечисления — дописать в `CARD_ENUMS` скрипта **после** решения по лору |
| C03 id и имя | повтор `id`; имя файла не находится в `name` | id уникален навсегда — ряд DataTable держится за него |
| C04 биомы и стихии | неизвестный биом или стихия; запись без `[[...]]` или вложенным списком `- - Вода` | привести к `biome: [[Болото]]` / `element: [[Вода]]` |
| C05 разделы карточек | нет обязательного раздела; `**` в заголовке | разделы — из схемы категории (`CARD_SCHEMA`) |
| C06 ссылки | битая `[[ссылка]]` (error); нет изображений (info, контентная задача) | направить на существующий термин или снять ссылку |
| C07 глоссарий | термин не в `_Index.md`; статус не `✅` / `🟡 частично` / `❌ не реализовано` | статус — по коду, не по желанию |
| C08 GDD | пропуск номера главы; раздел `N.M` не своей главы; повтор номера; глава не в индексе; `status: draft` (info) | draft в каноне — решение за автором: довести или вынести в `docs/design` |
| C09 ссылки на код | тип `AFoo`/`UFoo`/`FFoo`, файл `.h/.cpp`, тест или команда `Herbalist.*`, которых нет в коде | переименовано — поправить; удалено — снять или пометить в той же строке («раньше `X`», «удалено», «не существует», «до ГГГГ-ММ-ДД», «вместо `X`» — такие типы не ловятся; файлы и тесты проверяются всегда); ложная находка (тип движка) — `ENGINE_NAMES`; задуманное и сознательно не построенное — `PROPOSED_NAMES` с причиной |
| C10 ссылки на документы | `` `X.md` ``, которого нет в репозитории | чаще всего регистр или перенос файла |
| C11 легаси | резервные копии, разовые отчёты, `status: superseded` вне архива, спецификация `implemented` в `Future`, пути на чужих дисках, зачёркнутое в ROADMAP | удалить (история в git) или перенести; закрытое в ROADMAP — в CHANGELOG, из ROADMAP убрать |
| C12 индексы | документ `docs/` не в `docs/README.md`; коммандлет или скрипт не в `TOOLS_REFERENCE.md`; Exec- или консольная команда не описана в `docs/verification` | новая строка в индекс/гайд |
| C13 факты гайдов | эталон числа тестов разошёлся с кодом; карта по умолчанию не упомянута | обновить эталон после двух чистых прогонов |
| C14 данные | `id` растения нет в `CSV_tabs/ingredients.json`; `water_types.json` расходится с карточками биомов | порядок правды: документация → json → ассет |
| C15 маркеры (info) | TODO/TBD/FIXME/??? в каноне | решить или перенести в ROADMAP |
| C16 техснимки (info) | `03_Technical/Current` не менялся >30 дней при изменившемся коде | сверить снимок с кодом |

Проверки, где скрипт может ошибиться, помечены «ложная находка — куда
дописать». Правило одно: исключение дописывается в константу скрипта с
причиной, а не обходится молча.

## Шаг 2. Ручная часть — по разделам

Скрипт сверяет форму. Здесь — смысл. Каждый пункт — «да/нет», «нет» идёт в
промпт на обновление.

### Карточки компендиума

- [ ] Числа карточки согласуются с описанием: «ядовитая» трава не с
      `corruption: 0.05`, «чистый» биом не с высоким Distortion.
- [ ] Ассеты совпадают с карточками: `-run=BiomeDefaultsSync` пишет
      `приведено к документации значений: 0`; при сомнении — `-run=DataTableExport`
      и сравнение с `CSV_tabs` (`ENGINE_VERIFICATION_GUIDE.md`, уровень 2).
- [ ] Новая карточка есть в DataTable (или сознательно не заведена — тогда
      это сказано в карточке).
- [ ] Ареал, сушка, окна сбора в теле карточки не противоречат
      `ingredient_*_patch.json`.

### Главы GDD

- [ ] Главы не противоречат друг другу в одном и том же механизме (типичное
      место: числа Молвы, радиусы, пороги Clarity).
- [ ] Принятое из `docs/design/DESIGN_*.md` перенесено в главу, а черновик
      помечен «принято → глава N».
- [ ] Разделы «Статус / реализовано» глав совпадают с кодом и ROADMAP.
- [ ] `status: draft` у главы — осознанно (глава ещё обсуждается), а не
      забытая шапка.

### Глоссарий

- [ ] Термин называется одинаково в GDD, коде (комментарии, имена) и
      интерфейсе; синонимы — в `aliases`.
- [ ] Статус реализации термина совпадает с кодом.
- [ ] Новые понятия последних этапов (из CHANGELOG за период) заведены.

### Техснимки и инженерные документы

- [ ] `03_Technical/Current` описывает текущий код: структуры, этапы
      пайплайна, что сохраняется.
- [ ] `MATH_REFERENCE.md` — формулы и константы сверены с кодом после
      правок симуляции.
- [ ] `docs/verification` — эталоны (число тестов, строки паспорта мира)
      сняты с последнего прогона, а не переписаны из старого текста.
- [ ] `DECISIONS_LOG.md`: решения, на которые ссылается ROADMAP, не закрыты
      молча.

### Легаси

- [ ] Устаревшее — только в `03_Technical/Archive` и с плашкой «АРХИВ» в
      начале; канон на архив не ссылается как на источник истины.
- [ ] Разовые скрипты и отчёты не лежат в хранилище после того, как
      отработали.
- [ ] `ROADMAP.md` — только открытое.

## Шаг 3. Оформление

- Правки — отдельным коммитом «Документация: …», с числами прогона скрипта
  до и после.
- Запись в `CHANGELOG.md` — если менялся смысл (канон, эталоны, решения);
  опечатки и ссылки — только в сообщении коммита.
- Повторный прогон скрипта: ошибок 0, число предупреждений не выросло.
