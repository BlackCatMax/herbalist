# 7. Пользовательский опыт и интерфейс

## 7.1 Система восприятия (Perception)

Игрок не видит числовые значения параметров напрямую. Вместо этого система восприятия преобразует их в описания, визуальные и звуковые сигналы.

**Что видит игрок:**

| Параметр | Восприятие |
|:---|:---|
| Высокая potency | «Мощное зелье», «сильное действие» |
| Низкая potency | «Слабое», «едва заметное» |
| Высокая purity | «Чистое», «прозрачное», «без примесей» |
| Низкая purity | «Мутное», «с хлопьями», «противоречивое» |
| Высокая corruption | «Чувствуется гниль», «нечистая сила» |
| Высокий distortion | «Свойства пляшут», «не верится», «обманчивое» |

**Влияние clarity (ясности):**
- Низкая clarity → размытые описания, скрытые параметры, ложные сигналы
- Высокая clarity → точные описания, видна скрытая информация

**Влияние distortion (искажения):**
- Искажает отображение свойств
- Может показывать ложные эффекты
- Усложняет интерпретацию результата

## 7.2 Визуальные сигналы

**Состояние ресурсов:**
- Цвет, форма, свечение, анимация
- Признаки порчи (гниль, плесень, туман)
- Признаки чистоты (прозрачность, сияние)

**Алхимический процесс:**
- Цвет и интенсивность пламени
- Пар, пузырьки, свечение
- Звуки (шипение, треск, звон)

**Результат (зелье):**
- Цвет и прозрачность
- Свечение, искры, туман
- Поведение в бутылке (покоится, бурлит, пульсирует)

## 7.3 Интерфейс (UI)

**Травник (книга рецептов):**
- Записи о собранных растениях
- Заметки о результатах экспериментов
- Намёки на закономерности (не полные рецепты!)
- Рисунки, символы, фольклорные описания

**Инвентарь:**
- Ресурсы с визуальными индикаторами свойств
- Отдельный раздел для воды
- Ограничение по весу/объёму

**Алхимическая станция:**
- Слоты для ингредиентов (с указанием порядка)
- Выбор воды
- Кнопка запуска

**Индикаторы состояния:**
- Искажение (визуальный шум, дрожание шкал)
- Ясность (чёткость текста, детализация)
- Давление (анимация, звуки натяжения)

## 7.4 UX-принципы

1. **Информация должна быть достаточной, но не полной** – игрок должен думать, а не получать готовые ответы.

2. **Сигналы должны быть устойчивыми** – игрок должен учиться их распознавать.

3. **Ошибки должны быть возможны** – система допускает неверные выводы.

4. **Восприятие – часть геймплея** – интерпретация является активным процессом.

5. **Все сигналы должны быть связаны с параметрами** – никаких декоративных элементов без смысла.

## 7.5 Эволюция UI с прогрессией

Со временем (по мере накопления знаний и фрагментов памяти):

- Увеличивается объём доступной информации
- Снижается уровень шума
- Повышается читаемость
- Появляются точные числовые значения (при высоком знании)

Но система никогда не становится полностью прозрачной – сохраняется необходимость интерпретации.
