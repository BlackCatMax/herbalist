# CORE LOCK — Инварианты системы

Этот раздел фиксирует базовые инварианты системы «Herbalist».

Он не вводит новых механик.
Он определяет **единую модель**, которой подчиняются все остальные разделы.

## 0. Назначение

Все игровые процессы, восприятие и поведение мира должны быть объяснимы через единую систему.

Никакие отдельные механики, исключения или параллельные модели не допускаются.

## 1. Единое состояние мира

В игре существует одно состояние, описывающее мир: **BiomeState**

BiomeState является:

* единственным источником всех изменений
* единственным источником всех наблюдаемых проявлений
* единственной переменной, изменяющейся во времени

Любой эффект, поведение или наблюдение должны быть выводимы из BiomeState.

## 2. Переход состояния

Система развивается как последовательность состояний:

BiomeState(t) → BiomeState(t+1)

Переход между состояниями происходит только через действия игрока и системные процессы.
Никакие изменения не происходят вне этого перехода.

## 3. Единственный поток системы

Все взаимодействия описываются единым потоком:

Player → Action → Transformation → BiomeState → Perception → Player

Где:

* Player — субъект принятия решений
* Action — действие игрока
* Transformation — системная обработка (pipeline)
* BiomeState — результат изменения
* Perception — наблюдаемое проявление

Ни один элемент не может быть исключён или обойдён.
все взаимодействия в игре являются преобразованием состояния, распределённого в пространстве

## 4. Отсутствие параллельных систем

В игре отсутствуют:

* независимые механики
* скрытые правила, не выводимые из состояния
* отдельные системы, не связанные с BiomeState

Все системы (сбор, преобразование, среда, сущности) являются частями единой модели.

## 5. Роли ключевых компонентов

### Биомы

Биомы представляют собой локальные состояния BiomeState.

Они не являются отдельными системами, а являются его пространственным распределением.

### Сущности

Сущности являются проявлением состояния:

Entity = Projection(BiomeState)

Они:

* не влияют на систему
* не участвуют в вычислениях
* не являются агентами

Их функция — наблюдаемость.

### Преобразование (алхимия)

Результат преобразования определяется функцией:

Result = f(ingredients, BiomeState)

Никакие другие факторы не участвуют в формировании результата.

### Направленность (Intent)

Intent является свойством результата преобразования.

Он:

* не выбирается напрямую
* формируется в процессе преобразования
* влияет на характер изменения BiomeState

Intent не существует отдельно от результата.

### Капища

Капища являются локальными модификаторами состояния среды.

Они:

* не создают эффекты
* не изменяют результат напрямую
* влияют на устойчивость изменений

## 6. Причинность

Единственная допустимая причинная цепочка:

Player → изменение BiomeState → изменение мира → восприятие

Обратная причинность отсутствует.
Сущности, ресурсы и визуальные элементы не могут быть источником изменения состояния.

## 7. Восприятие

Игрок не взаимодействует с системой напрямую.

Он воспринимает:

* проявления среды
* поведение ресурсов
* проявления сущностей

Восприятие:

* может быть неполным
* может быть искажённым
* требует интерпретации

## 8. Ошибка как часть системы

Ошибки интерпретации игрока являются частью системы.

Система не гарантирует:

* точности понимания
* предсказуемости результата

Ошибки не исправляются автоматически.
Они приводят к изменению состояния и формируют опыт.

## 9. Локальность и распространение

Изменения происходят локально, но могут распространяться.
Распространение определяется состоянием среды.
Не существует мгновенного глобального изменения.

## 10. Накопление

Система обладает памятью.

Изменения:

* сохраняются
* взаимодействуют друг с другом
* формируют долгосрочные состояния

Возврат к исходному состоянию не гарантирован.

## 11. Ограничения

Запрещено:

* вводить механики, не выводимые из BiomeState
* добавлять сущностям агентность
* создавать прямые “бонусы” вне состояния
* нарушать единый поток системы

## 12. Целостность

Система считается корректной, если:

* любое наблюдение объяснимо через BiomeState
* любое изменение проходит через единый поток
* отсутствуют противоречия между разделами
