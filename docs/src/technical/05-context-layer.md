# 5. СЛОЙ КОНТЕКСТА

## 5.1 Определение контекста

Контекст — совокупность внешних условий, влияющих на результат преобразования.

Контекст:
- не является частью Vector
- не изменяет структуру модели
- влияет только через коэффициенты (`k_axis`, `k_meta`)

**Структура контекста:**

Context = {
    # Временные параметры
    time: Time = {
        time_of_day: float,   # ∈ [0, 1] — 0=полночь, 0.5=полдень, 1=след. полночь
        season: float,        # ∈ [0, 1] — 0=весна, 0.5=лето/осень, 1=зима
        moon_phase: float     # ∈ [0, 1] — 0=новолуние, 0.5=полнолуние
    },
    
    # Глобальные параметры мира
    world: World = {
        toxicity: float,      # ∈ [0, 1] — загрязнение среды
        altitude: float       # ∈ [0, 1] — высота над уровнем моря
    },
    
    # Локальные параметры экосистемы
    ecosystem: Ecosystem = {
        fertility: float,     # ∈ [0, 1] — плодородие почвы
        moisture: float,      # ∈ [0, 1] — влажность
        competition: float,   # ∈ [0, 1] — конкуренция с другими растениями
        disturbance: float    # ∈ [0, 1] — нарушенность (пожары, выпас)
    },
    
    # Активные сущности в локации
    entities: List[Entity]    # см. раздел 4.2
}

Контекст передаётся в Process System как отдельная структура и используется:
- для вычисления контекстных коэффициентов (разделы 5.2-5.6)
- для модификации процесса сбора (раздел 6.1)
- для определения присутствия сущностей (раздел 4.2.5)

### Система времени (Time System)

Описывает временные параметры:
- time_of_day: float,   # ∈ [0, 1] — 0=полночь, 0.5=полдень, 1=след. полночь
- season: float,        # ∈ [0, 1] — 0=весна, 0.5=лето/осень, 1=зима
- moon_phase: float     # ∈ [0, 1] — 0=новолуние, 0.5=полнолуние

Представление: непрерывные или циклические значения.

### Система мира (World System)

Описывает глобальные параметры среды:
- toxicity: float,      # ∈ [0, 1] – загрязнение, ядовитость среды (0 – чисто, 1 – смертельно)
- altitude: float       # ∈ [0, 1] – относительная высота над уровнем моря (0 – равнина, 1 – высокогорье)

### Экосистемы (Ecosystem System)

Описывает локальное окружение:
- fertility: float,     # ∈ [0, 1] – плодородие почвы
- moisture: float,      # ∈ [0, 1] – влажность почвы (0 – сухо, 1 – переувлажнено)
- competition: float,   # ∈ [0, 1] – конкуренция с другими растениями
- disturbance: float    # ∈ [0, 1] – нарушенность (пожары, выпас, ветровалы)

**Контекст передаётся в Process System как отдельная структура и используется:**
- для вычисления контекстных коэффициентов (разделы 5.2-5.6)
- для модификации процесса сбора (раздел 6.1)
- для определения присутствия сущностей (раздел 4.2.5)

## 5.6 Правила комбинирования контекста — исправленная версия

Контекстные коэффициенты объединяются в итоговые значения `k_axis_total` и `k_meta_total`, используемые в Process System.

## Общий принцип

Все коэффициенты агрегируются через **аддитивное отклонение от единицы**:
`k_total = 1 + Σ(k_i - 1)`

## Итоговые коэффициенты

### Для осей

`k_axis_total = 1
- (k_axis_time_total - 1)
- (k_axis_world - 1)
- (k_axis_eco - 1)`

### Для meta

`k_meta_total = 1
- (k_meta_time_total - 1)
- (k_meta_world - 1)
- (k_meta_eco - 1)`

## Нормированный вариант (опционально)

При необходимости ослабления влияния контекста:
`k_total = 1 + (Σ(k_i - 1)) / N`
где `N` — количество источников (обычно 3).
Базовая версия использует **ненормированную форму** (без деления).

## Ограничения

- **k_axis_total:**
  - не ограничивается
  - может быть < 0 (инверсия осей)
  - может превышать 2
  
- **k_meta_total:**
  - если `< 0`, заменяется на `0`
  - верхняя граница отсутствует

- clamp не применяется

## Поведение системы

Экстремальные значения:
- `k_axis_total > 2`
- `k_axis_total < -1`
- `k_meta_total > 2`

считаются допустимыми и формируют **нестабильные игровые зоны**.

## Правило границ интерпретации

При экстремальных коэффициентах:
- значения axes могут выходить за диапазон `[-2, 2]` и более
- значения meta могут выходить за диапазон `[0, 2]` и более

Система:
- не прерывает вычисления
- не применяет clamp
- передаёт значения дальше по пайплайну

## Интерпретация в игре

Нестабильные зоны могут проявляться как:
- резкие усиления эффектов
- искажённые свойства
- нестабильные результаты

Это расширяет пространство экспериментов, не нарушая детерминизм.

## Применение

`axes = axes × k_axis_total`
`meta = meta × k_meta_total`

## Инварианты этапа

- все источники контекста равноправны
- контекст не изменяет структуру Vector
- контекст применяется только через коэффициенты
- entities в контексте не влияют на Process System напрямую (только через BehaviorTags в Input Assembly)

Результат этапа — агрегированные контекстные коэффициенты, готовые к применению в Process System.

## Применение

Этап выполняется:
- после комбинирования контекста (раздел 5.6)
- до Water Application
- внутри Process System (как часть Context Modifiers)

## 5.8 Вода как основа (Water Base)

## Определение

Вода — это **выбираемый аддитивный модификатор**, применяемый в Process System.

Характеристики:
- не является Resource
- не имеет BehaviorTags
- не участвует в Input Assembly
- не входит в Vector
- не сохраняется в результате

Вода применяется как часть пайплайна на этапе **Water Application**.

## Позиция в пайплайне

Water Application выполняется:
- после Context Modifiers
- до Axis Sign Modifiers
- до Interaction Rules

## Формализация применения

Для выбранного типа воды с параметрами `Δ_axes`, `Δ_meta`:

### Оси
`axes = axes + Δ_axes`

### Meta
`meta = meta + Δ_meta`

## Ограничения

- вода не изменяет:
  - `resonance`
  - `distortion`

- отсутствует clamp

- допускается выход значений за диапазоны

## Типы воды (структура данных)

Каждый тип воды задаётся как:
`Water = {Δbody, Δmind, Δspirit, Δnature, Δpotency, Δpurity, Δstability, Δcorruption, Δpressure}`

## Влияние на modifiers

Вода может изменять modifier:
`pressure = pressure + Δpressure`

Это влияет на Morok, но не нарушает структуру модели.

## Баланс и trade-off

Сильные типы воды имеют встроенные компенсации:
- увеличение `pressure` → усиление Morok
- снижение `stability` → усиление Collapse
- рост `corruption` → усиление искажения

Это обеспечивает отсутствие доминирующего выбора.

## Свойства системы

- вода — единственный выбираемый игроком модификатор процесса
- влияние полностью детерминировано
- отсутствуют скрытые эффекты

## Использование

- выбирается перед началом Process System
- если вода не выбрана → используется нулевая (Δ = 0)

## Инварианты этапа

- применяется ровно один раз
- не влияет на структуру Vector
- не взаимодействует напрямую с Interaction Rules
- не создаёт новых параметров

Результат этапа — модифицированное состояние, учитывающее выбранную основу процесса.
