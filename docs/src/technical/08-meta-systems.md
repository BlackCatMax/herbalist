# 8. МЕТА-СИСТЕМЫ

## 8.1 Система памяти (Memory System)

Memory System хранит агрегированную информацию о предыдущих результатах и влияет на последующие вычисления через ограниченный набор параметров.

### Назначение

- вводит **инерцию системы**
- обеспечивает **накопление эффектов**
- **хранит историю отношения игрока к миру** (уважение к сущностям)
- не нарушает детерминизм

### Хранимые параметры

Memory = {
    # Существующие параметры
    last_distortion: float,      # distortion последнего результата
    corruption_memory: float,    # сглаженное значение corruption
    clarity: float,              # чистота истории
    
    # НОВЫЙ параметр
    respect_score: float         # ∈ [-1, 1] — накопленное уважение сущностей
}

### Обновление памяти

После формирования Result Vector:

# Существующие обновления
last_distortion = distortion
corruption_memory = lerp(corruption_memory, corruption, K_MEMORY_CORR_BLEND)
clarity = lerp(clarity, purity, K_MEMORY_CLARITY_BLEND)

# Обновление respect_score на основе действий игрока
respect_score += Δrespect
respect_score = clamp(respect_score, -1, 1)

### Изменение respect_score (Δrespect)

| Действие игрока | Условие | Δrespect |
|:---|:---|:---:|
| Сбор целебных трав | в лесу, без лишнего шума | +0.02 |
| Сбор без уважения | вырывание с корнем, поломка веток | -0.03 |
| Использование чистого зелья | purity > 0.8 | +0.01 |
| Использование коррумпированного зелья | corruption > 0.5 | -0.02 |
| Оставление подношения | сущности (по специальному действию) | +0.05 |
| Длительное пребывание | в одной локации (за час) | +0.01 |

#### Применение нескольких Δrespect

За одно действие может быть выполнено несколько условий из таблицы Δrespect. **Все применимые Δrespect суммируются.**

Пример: игрок собирает целебные травы в лесу, не шумя, и у него уже есть высокое уважение.

Δrespect = +0.02 (сбор целебных трав) + 0.02 (лес, без шума) = +0.04

Итоговое обновление:
```
respect_score = clamp(respect_score + Δrespect, -1, 1)
```

Если действие не подходит ни под одно условие, Δrespect = 0.

### Использование respect_score

`respect_score` используется в:

1. **Attitude System сущностей**:
   if entity.archetype == HOST:
       respect_mod = player.respect_score * entity.respect_sensitivity

2. **Формуле присутствия сущностей**:
   if entity.archetype in [HOST, ANCESTOR]:
       behavioral_factor = 1 + player.respect_score * entity.respect_sensitivity

### Свойства обновления

- используются только линейные операции
- отсутствуют ветвления
- значения не ограничиваются clamp (кроме финального)

### Инициализация

При отсутствии предыдущих данных:
last_distortion = 0
corruption_memory = 0
clarity = 1
respect_score = 0  # нейтральное отношение


### Инварианты

- Memory обновляется **после завершения пайплайна**
- не изменяется в процессе вычислений
- не содержит скрытых параметров
- не нарушает структуру Vector
- **respect_score влияет только на сущностей, не на алхимию**

Результат — обновлённое состояние памяти, влияющее на последующие циклы системы.

### Конфигурационные параметры

| Константа | Значение | Описание |
|-----------|----------|----------|
| `K_MEMORY_CORR_BLEND` | 0.2 | Сглаживание corruption |
| `K_MEMORY_CLARITY_BLEND` | 0.2 | Сглаживание clarity |
| `K_RESPECT_DECAY` | 0.01 | Естественное затухание respect_score за цикл |

## 8.2 Система давления (Pressure System)

Pressure System моделирует интенсивность воздействия на систему.

**Свойства:**
- скалярный параметр `pressure` [0,1]
- зависит от условий процесса (Alchemy) и количества ингредиентов

**Формирование** (см. раздел 6.2):

`pressure = K_PRESSURE_BASE + K_PRESSURE_COUNT × (N / N_max)`

где:
- `N` — количество ресурсов
- `N_max` — нормировочный максимум (по умолчанию 10)
- `K_PRESSURE_BASE` — базовое давление (по умолчанию 0.1)
- `K_PRESSURE_COUNT` — коэффициент влияния количества (по умолчанию 0.3)

**Примечание:** Параметры `temperature`, `duration`, `method` не входят в вычислительную модель. Если они используются в геймплее, они должны влиять на `pressure` через модификаторы контекста или через параметр `intensity` (который агрегируется в `pressure` через отдельный коэффициент, см. раздел 6.2).

**Влияние:**
- усиливает эффект Morok (через λ)
- влияет на Conflict Resolution (через `stability_eff = stability × (1 - pressure × CR_PRESSURE_STABILITY_FACTOR)`)
- не изменяет параметры напрямую
- действует только через указанные механизмы

## 8.3 Распространение искажения и эволюция мира (Distortion Propagation & World Evolution)

Система переноса и накопления искажения между процессами и долгосрочного изменения мира.

### Функции

- перенос части distortion в будущие состояния (через `corruption_memory`)
- формирование долгосрочных эффектов на экосистему и мир
- **локальное влияние сущностей на мир (Entity → World Influence)**
- **локальная обратная связь от сбора к миру (Harvest → World Feedback)**
- **глобальная эволюция мира от алхимии**


### Три канала влияния на мир

| Канал | Раздел | Когда | Масштаб | Сила (макс. изменение) |
|:---|:---|:---|:---|:---|
| **World Evolution (алхимия)** | 8.3 | После создания зелья | Глобальный | 0.01 (toxicity, disturbance) / 0.005 (fertility, competition) |
| **Harvest → World** | 4.2.8 | При сборе ресурса | Локальный | 0.1 × интенсивность × множитель тега |
| **Entity → World** | 4.2.7 | При сборе ресурса | Локальный | 0.1 × интенсивность × множитель тега |


### 1. Обратная связь от алхимии к миру (глобальная)

Применяется после каждого успешного создания Resource final:

world.toxicity += EVOLVE_TOXICITY_STEP * (corruption - 0.5)
ecosystem.disturbance += EVOLVE_DISTURBANCE_STEP * (distortion - 0.5)
ecosystem.fertility += EVOLVE_FERTILITY_STEP * (resonance - 0.5)
ecosystem.competition += EVOLVE_COMPETITION_STEP * (0.5 - purity)

# Нормализация
world.toxicity = clamp(world.toxicity, 0, 1)
ecosystem.disturbance = clamp(ecosystem.disturbance, 0, 1)
ecosystem.fertility = clamp(ecosystem.fertility, 0, 1)
ecosystem.competition = clamp(ecosystem.competition, 0, 1)

**Интерпретация:**
- Высокая `corruption` → рост токсичности мира
- Высокий `distortion` → рост нарушенности
- Высокий `resonance` → рост плодородия
- Высокая `purity` → снижение конкуренции


### 2. Обратная связь от сбора к миру (локальная)

Применяется в момент сбора ресурса (см. раздел 4.2.8):

for tag in harvested_resource.tags:
    if tag in WORLD_EFFECT_MAP:
        Δ = WORLD_EFFECT_MAP[tag]
        world.fertility += Δ.fertility * harvested_resource.intensity * K_HARVEST_IMPACT
        world.moisture += Δ.moisture * harvested_resource.intensity * K_HARVEST_IMPACT
        world.competition += Δ.competition * harvested_resource.intensity * K_HARVEST_IMPACT
        world.disturbance += Δ.disturbance * harvested_resource.intensity * K_HARVEST_IMPACT
        world.toxicity += Δ.toxicity * harvested_resource.intensity * K_HARVEST_IMPACT

# Нормализация
for param in [fertility, moisture, competition, disturbance, toxicity]:
    world[param] = clamp(world[param], 0, 1)


### 3. Влияние сущностей на мир (локальное)

Применяется в момент сбора ресурса (см. раздел 4.2.7):

for entity in entities_in_location:
    for tag in entity.tags:
        if tag in WORLD_EFFECT_MAP:
            Δ = WORLD_EFFECT_MAP[tag]
            world.fertility += Δ.fertility * entity.intensity * K_ENTITY_WORLD_INFLUENCE
            world.moisture += Δ.moisture * entity.intensity * K_ENTITY_WORLD_INFLUENCE
            world.competition += Δ.competition * entity.intensity * K_ENTITY_WORLD_INFLUENCE
            world.disturbance += Δ.disturbance * entity.intensity * K_ENTITY_WORLD_INFLUENCE
            world.toxicity += Δ.toxicity * entity.intensity * K_ENTITY_WORLD_INFLUENCE

# Нормализация
for param in [fertility, moisture, competition, disturbance, toxicity]:
    world[param] = clamp(world[param], 0, 1)

|-----------|----------|----------|

| `EVOLVE_FERTILITY_STEP` | 0.005 | Шаг изменения плодородия от алхимии |

### Инварианты

- Все изменения после применения clamp в [0,1]
- Влияние сбора и сущностей слабее влияния алхимии (коэффициент 0.1)
- Локальные изменения (сбор, сущности) не переопределяют глобальную эволюцию
- Глобальная эволюция (алхимия) не отменяет локальные изменения
- Система остаётся детерминированной

## 8.4 Система знаний (Knowledge System)

Knowledge System определяет уровень понимания игроком механик и свойств ресурсов.

**Свойства:**
- не влияет на расчёты Process System
- используется только в Perception System
- накапливает наблюдения (`input` → `output`) и паттерны

**Влияние на Perception:**
- изменяет детализацию информации
- влияет на точность описаний
- открывает новые интерпретации (например, при высоком знании игрок видит точные числовые значения, при низком – только размытые категории)

**Пример:**
- низкое знание → общее описание («травяной настой»)
- высокое знание → точные параметры («potency 0.73, corruption 0.12»)

**Ограничения:**
- не изменяет Resource
- не влияет на Process System
- не участвует в формировании modifiers

## 8.5 Система прогрессии (Progression System)

Progression System управляет развитием игрока и открытием новых возможностей.

**Функции:**
- открытие новых источников (Resources, Entities)
- открытие новых действий в Alchemy System
- изменение доступных рецептов (не самих формул, а разрешения на использование)

**Свойства:**
- не изменяет Vector напрямую
- не вмешивается в Process System
- не изменяет modifiers или context
- влияние осуществляется только на уровне доступа (до Input Assembly)

**Формально:**
available_inputs = filter(Sources, Progression.level)
available_processes = filter(Alchemy.actions, Progression.level)

### Прогрессия для воды

Система прогрессии влияет на воду следующим образом:

- **Увеличение ёмкости для воды** – за выполнение определённых достижений (например, «собрать 10 разных растений», «создать 50 зелий»)
	или покупку улучшений игрок получает повышение `max_water_capacity`. Конкретные шаги: +1 за каждое достижение, максимальное значение задаётся в конфигурации.
- **Открытие доступа к новым источникам воды** – обряды освящения (живая вода) и омертвления (мёртвая вода) требуют
	наличия соответствующих знаний или разрешений (например, после выполнения квеста или достижения определённого уровня в алхимии).
- **Улучшение сбора воды** – автоматический сбор дождевой воды, возможность собирать росу без специального предмета,
	увеличение количества воды, получаемой за одно действие (например, 2 единицы вместо 1). Всё это открывается по мере прогрессии.

Все изменения, связанные с водой, не нарушают инвариантов CORE, так как влияют только на доступность и количество воды, но не на формулы преобразования.

## Инварианты мета-систем

- Мета-системы не изменяют axes и meta напрямую.
- Влияние осуществляется только через modifiers, context или perception.
- Текущий Resource не изменяется (кроме создания нового).
- Изменения проявляются только в будущих вычислениях.
- Все преобразования (где применимо) остаются линейными или пропорциональными (исключение – накопление через `corruption_memory`, которое является линейным накоплением).
