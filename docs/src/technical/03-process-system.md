# 3. СЛОЙ ПРЕОБРАЗОВАНИЯ (PROCESS SYSTEM)

## **Process System** как динамическая система (каноническое описание)

**Process System** представляет собой замкнутую динамическую систему, в которой состояние изменяется через приращения, искажённые Morok, ограниченные Stability и структурированные Zaryana, с обратной связью через Memory System.

Формально:

1. Приращение Δ формируется на основе текущих осей, potency и исторического искажения (Bootstrap).
2. Morok нелинейно искажает Δ (но не само состояние).
3. Искажённое приращение Δ_morok добавляется к текущему состоянию.
4. Stability управляет коллапсом: при падении ниже порога состояние плавно деградирует.
	Collapse является частью этапа Conflict Resolution и не выделяется в отдельный этап пайплайна.
5. Zaryana не уничтожает, а структурирует результат через интерполяцию между искажённым состоянием и его структурированной формой ψ(S).
6. Memory System сохраняет last_distortion, замыкая петлю обратной связи для будущих итераций.

Ключевые свойства: детерминизм, непрерывность, отсутствие ветвлений, замкнутость.

## Определение состояния и шага преобразования

Система рассматривается как одношаговое преобразование без внутренней итерации:

`S_out = Process(S_in, context, modifiers)`

где:
	S_in – входной вектор (axes, meta без distortion) после Input Assembly;
	S_out – резульчатый вектор (axes, meta c distortion);
	Δ вычисляется внутри Process System как вспомогательная величина и не сохраняется между вызовами.

Динамика во времени (эволюция мира, обновление памяти) происходит между вызовами Process System, а не внутри него.
Это гарантирует детерминизм, отсутствие скрытых состояний и лёгкость тестирования.

## 3.1 Система обработки (Process System)

**Process System** — единый слой, в котором выполняются все преобразования параметров.

**Вход**: GameplayParams (axes, meta, modifiers, context)
**Выход**: Result Vector (axes, meta + distortion)

Характеристики:
- отсутствуют ветвления (if/else)
- все операции детерминированы
- преобразования выполняются последовательно

Порядок обработки фиксирован и не изменяется.

## 3.2 Уточнение агрегации (Aggregation Refinement)

На этом этапе агрегированные входные значения преобразуются в начальное состояние для динамики процесса.

### Основная операция

Для каждой оси:

`axis = axis × potency + κ × last_distortion`

где:
 κ = BOOTSTRAP_GAIN (конфигурационная константа, по умолчанию 0.1)
 last_distortion — значение distortion последнего созданного ресурса (из Memory System)

При первом запуске:
`last_distortion = 0`

### Применение к мета-параметрам

Aggregation Refinement применяется **только к осям (axes)**.
Мета-параметры (potency, purity, stability, resonance, corruption) на этом этапе **не изменяются**.

Обоснование: Мета-параметры описывают свойства состояния, а не направленность.
Их трансформация происходит на следующих этапах (Context Modifiers, Interaction Rules, Morok).

### Свойства этапа

- все операции линейны
- не используется clamp
- результат может выходить за пределы [-1,1]
- создаётся начальное состояние S₀ для Process System

### Определение приращения Δ

После Aggregation Refinement вычисляется приращение Δ, используемое **исключительно в Morok**.

#### Базовые компоненты

Для осей:

`Δ_axes = axes × potency × K_AXIS_GAIN`

Для мета-параметров:

`Δ_meta = (meta - 0.5) × potency × K_META_GAIN`

Применяется к:

- potency
- purity
- stability
- resonance
- corruption

`distortion` не участвует в вычислении Δ.

#### Bootstrap-компонента

`Δ_bootstrap = κ × last_distortion`

Применяется с учётом направления:

`Δ_axes_total = Δ_axes + sign(axes) × Δ_bootstrap`
`Δ_meta_total = Δ_meta + sign(meta - 0.5) × Δ_bootstrap`

где:
 sign(0) = 0
 знак определяет направление усиления

### Итоговое приращение

`Δ = (Δ_axes_total, Δ_meta_total)`

**Свойства Δ**
- Δ не является частью состояния (не входит в Vector)
- Δ не сохраняется между вызовами Process System
- Δ может принимать любые значения (не ограничен диапазоном)
- Δ не нормализуется перед Morok

### Динамическая устойчивость

Bootstrap создаёт положительную обратную связь:
- при росте distortion усиливается Δ
- это может приводить к ускоренной деградации состояния

Ограничения:
- рекомендуется: `κ ≤ 0.1`
- при необходимости:
  - ограничивать last_distortion в Memory System;
  - вводить затухание памяти

### Инварианты этапа
- Δ вычисляется строго один раз
- Δ используется только в Morok
- Δ не влияет на состояние напрямую (только через Δ_morok)
- отсутствуют нелинейные преобразования

Результат этапа: подготовленное состояние S и приращение Δ для последующих преобразований.

## 3.3 Контекстные модификаторы (Context Modifiers)

Контекст преобразуется в коэффициенты `k_axis_total` и `k_meta_total` (см. раздел 5) и применяется к состоянию мультипликативно.

### Применение коэффициентов

`axes = axes × k_axis_total`
`meta = meta × k_meta_total`

### Ограничения

- Для **meta**:
  если `k_meta_total < 0`, то `k_meta_total = 0`

- Для **axes**:
  отрицательные значения `k_axis_total` допустимы и интерпретируются как инверсия осей

- clamp не применяется

- значения могут выходить за диапазоны

## Применение в пайплайне (исправленная последовательность)

Порядок операций строго фиксирован:

1. **Context Modifiers** (мультипликативно)
2. **Water Application** (аддитивно)
3. **Axis Sign Modifiers** (непрерывные модификаторы)
4. **Interaction Rules**

Все операции выполняются без clamp.

## Water Application (формализация)

После применения контекста добавляются модификаторы выбранной воды.

Для осей:
for each ax in {body, mind, spirit, nature}:
    axes[ax] = axes[ax] + Δax

Для meta:
for each m in {potency, purity, stability, corruption}:
    meta[m] = meta[m] + Δm


### Ограничения Water Application

- `resonance` не изменяется водой напрямую
- `distortion` не изменяется водой
- значения могут выходить за допустимые диапазоны
- clamp отсутствует

## Axis Sign Modifiers (непрерывные модификаторы) — исправленная версия

Этап выполняется после Water Application.

Все функции непрерывны, без ветвлений и без clamp.

### Мера отрицательности

sign_mix = (
    max(0, -body) +
    max(0, -mind) +
    max(0, -spirit) +
    max(0, -nature)
) / 4

### Поправки от отрицательности

corruption = corruption + K_SIGN_CORRUPTION × sign_mix
purity     = purity     - K_SIGN_PURITY × sign_mix

### Гармония

harmony = 1 - sign_mix

potency   = potency   + K_SIGN_POTENCY × harmony
stability = stability + K_SIGN_STABILITY × harmony

### Конфликты осей

**Тело ↔ дух:**

conflict_bs = (max(0, -body × spirit)) ^ CONFLICT_POWER
corruption  = corruption + K_CONFLICT_CORRUPTION × conflict_bs

**Разум ↔ природа:**

conflict_mn = (max(0, -mind × nature)) ^ CONFLICT_POWER
stability   = stability - K_CONFLICT_STABILITY × conflict_mn

### Свойства этапа

- все изменения аддитивны
- отсутствуют ветвления
- отсутствует clamp
- допускается выход за диапазоны
- используются только локальные значения axes

### Конфигурационные параметры

Все коэффициенты вынесены в раздел 10.7:

- `K_SIGN_CORRUPTION`
- `K_SIGN_PURITY`
- `K_SIGN_POTENCY`
- `K_SIGN_STABILITY`
- `K_CONFLICT_CORRUPTION`
- `K_CONFLICT_STABILITY`
- `CONFLICT_POWER`

### Инварианты этапа

- Context применяется строго до Interaction Rules
- Water не участвует в Interaction Rules напрямую
- все модификации выполняются до Morok
- этап не изменяет структуру Vector

## 3.4 Правила взаимодействия (Interaction Rules) — исправленная версия

Interaction Rules — это детерминированный набор преобразований, применяемых к состоянию после этапа Axis Sign Modifiers.

### Общие свойства

- порядок строго фиксирован
- отсутствуют ветвления (if/else)
- используются только локальные значения состояния
- отсутствует clamp
- допускается выход значений за диапазоны
- все преобразования применяются последовательно

Результат этапа: **S_interacted**

### Обозначения

- `axes = {body, mind, spirit, nature}`
- `meta = {potency, purity, stability, resonance, corruption}`
- `sign(x)` определён как 0 при x = 0

## Фиксированный порядок правил

1. Усиление от резонанса
for each axis in axes:
    axis = axis × (1 + K_RES_GAIN × resonance)

2. Синергия
for each axis in axes:
    axis = axis × (1 + K_SYNERGY_GAIN × resonance)

3. Разложение через коррупцию
for each axis in axes:
    axis = axis × (1 - corruption × sign(axis))

4. Эффективная коррупция (вычисление)
effective_corruption = corruption × (1 - purity)
Не изменяет состояние напрямую, используется концептуально и может применяться в расширениях.

5. Резонанс через выравнивание
alignment = (body + mind + spirit + nature) / 4
for each axis in axes:
    axis = axis × (1 + resonance × alignment)

6. Антагонизм силы и стабильности (одновременное обновление)
old_pot = potency
old_stab = stability
stability = old_stab - K_POTENCY_TO_STABILITY × old_pot
potency   = old_pot - K_STABILITY_TO_POTENCY × (1 - old_stab)

7. Связь коррупции и чистоты (одновременное обновление)
old_corr = corruption
old_pur  = purity
purity     = old_pur  - old_corr
corruption = old_corr - K_PURITY_TO_CORRUPTION × old_pur

8. Диссонанс осей
resonance = resonance - K_AXIS_DIVERGENCE × abs(body - nature)

## Свойства вычислений

- правила 6 и 7 используют значения на входе (одновременное обновление)
- остальные правила применяются последовательно
- все коэффициенты вынесены в конфигурацию

## Конфигурационные параметры

(см. раздел 10.7)

- `K_RES_GAIN`
- `K_SYNERGY_GAIN`
- `K_POTENCY_TO_STABILITY`
- `K_STABILITY_TO_POTENCY`
- `K_PURITY_TO_CORRUPTION`
- `K_AXIS_DIVERGENCE`

## Инварианты этапа

- Interaction Rules не используют modifiers напрямую
- Interaction Rules не изменяют distortion
- все преобразования выполняются до Morok
- отсутствуют нелинейные искажения Δ
- структура Vector сохраняется

Результат этапа — состояние, подготовленное для применения **Morok**.

## 3.5 Морок (Morok)

**Morok** — единственный механизм нелинейного искажения в системе.
Он применяется **к приращению Δ**, а не к состоянию S напрямую.

## Общая схема

1. Вычисляется коэффициент искажения `λ`
2. Формируется искажённое приращение `Δ_morok`
3. Обновляется состояние: `S_new = S_old + Δ_morok`
4. Значение `distortion = λ` сохраняется в meta

## Вычисление λ (distortion)

**Базовое значение**
`λ_raw = corruption × (1 - purity) × (1 + pressure) × (1 + corruption_memory) × (1 - clarity)`

**Защитное ограничение**
`λ_raw = clamp(λ_raw, 0, 1)`

Это единственный допустимый промежуточный clamp.

**Геометрический фактор осей**
`μ = (body + mind + spirit + nature) / 4`
`chaos = sqrt( ((body - μ)^2 + (mind - μ)^2 + (spirit - μ)^2 + (nature - μ)^2) / 4 )`
`base = (abs(body) + abs(mind) + abs(spirit) + abs(nature)) / 4`

**Усиление и финальное значение**
`λ_axis_factor = 1 + base × chaos`
`λ = clamp( (λ_raw × λ_axis_factor) ^ K_MOROK_POWER , 0, 1)`

### Вспомогательная функция deterministic_noise

Используется в Perception System (раздел 11.5) для детерминированного искажения отображаемых значений.

```
seed = int(value * 10000) ^ (fragments * 123456789)
h = seed
h = (h ^ (h >> 16)) * 0x85EBCA77
h = (h ^ (h >> 13)) * 0xC2B2AE35
h = h ^ (h >> 16)
r = (h % 1000000) / 1000000.0 # [0, 1)
return (r - 0.5) * 2 * max_noise
```

Параметры:
- `value` — исходное значение параметра
- `fragments` — количество собранных фрагментов памяти (0..12)
- `max_noise` — максимальная амплитуда шума (например, 0.3)

Свойства:
- Детерминированность: одинаковые входы → одинаковый выход
- Зависит от прогрессии (fragments): чем больше фрагментов, тем меньше эффективный шум


## Искажение приращения Δ

**Вес нелинейности**
`s = clamp((λ - MOROK_SMOOTHSTEP_LOW) / (MOROK_SMOOTHSTEP_HIGH - MOROK_SMOOTHSTEP_LOW), 0, 1)`
`w = s × s × (3 - 2 × s)`  (smoothstep)

**Основная формула**
`Δ_morok = Δ             + λ × (sign(Δ) × (1 - abs(Δ)))             + w × (λ^2) × (Δ - sign(Δ) × K_MOROK_SHIFT)`

**Обновление состояния**
`S_new = S_old + Δ_morok`

## Свойства этапа

- отсутствуют ветвления
- отсутствует clamp состояния
- допускается любой диапазон значений Δ и S
- искажение зависит от:
  - corruption
  - purity
  - pressure
  - corruption_memory
  - clarity
  - геометрии осей

## Работа с Δ

- Δ не нормализуется перед Morok
- Δ может иметь любые значения
- Morok:
  - усиливает крайние значения
  - смещает Δ к полюсам
  - добавляет нелинейную компоненту

## Параметры конфигурации

(см. раздел 10.7)

- `K_MOROK_POWER`
- `MOROK_SMOOTHSTEP_LOW`
- `MOROK_SMOOTHSTEP_HIGH`
- `K_MOROK_SHIFT`

## Инварианты этапа

- Morok — единственный этап, искажающий Δ
- Morok не изменяет структуру Vector
- distortion вычисляется только здесь
- distortion не участвует в вычислении Δ
- результат передаётся в Conflict Resolution

Результат этапа: обновлённое состояние S и вычисленный параметр distortion.

## 3.6 Разрешение конфликтов (Conflict Resolution)

Этап обрабатывает противоречия между осями, сглаживая их без потери общей «энергии» системы.

### Основное преобразование

Вычисляется среднее значение осей:
avg_axis = (body + mind + spirit + nature) / 4

### Эффективная стабильность с учётом давления

stability_eff = stability × (1 - pressure × CR_PRESSURE_STABILITY_FACTOR)

где `CR_PRESSURE_STABILITY_FACTOR` — конфигурационная константа (значение 1.0, см. раздел 10.7.8). Позволяет при необходимости ослабить или усилить влияние pressure на стабильность.

### Сближение осей
body = lerp(body, avg_axis, stability_eff)
mind = lerp(mind, avg_axis, stability_eff)
spirit = lerp(spirit, avg_axis, stability_eff)
nature = lerp(nature, avg_axis, stability_eff)

где `lerp(a, b, t) = a + (b - a) × t`.

### Свойства этапа

- уменьшает расхождения между осями
- не обнуляет значения
- сохраняет общую структуру состояния
- работает непрерывно (без порогов)

### Поведение при крайних значениях

- `stability_eff → 0` → оси остаются почти без изменений
- `stability_eff → 1` → оси сходятся к среднему значению

### Влияние pressure

- единственный modifier, влияющий напрямую на состояние на этом этапе
- увеличивает степень конфликта через снижение `stability_eff`
- усиливает расхождение осей

### Ограничения

- clamp не применяется
- значения могут выходить за диапазоны
- meta-параметры (кроме использования stability) не изменяются

### Collapse (встроенный механизм)

Collapse является внутренней частью этапа Conflict Resolution.

Если стабильность низкая, система деградирует плавно.

Параметр:
ε = COLLAPSE_THRESHOLD

Фактор схлопывания:
t = clamp(stability / ε, 0, 1)

Применение:
axes = axes × t

Свойства:
- выполняется внутри Conflict Resolution
- не является отдельным этапом pipeline
- не нарушает непрерывность
- использует только текущие значения состояния

### Инварианты этапа

- применяется после Morok
- выполняется до Zaryana
- не изменяет distortion
- не использует ветвления
- не вводит новых параметров

Результат этапа — сглаженное и, при необходимости, деградированное состояние, подготовленное для структурирования через Zaryana.

## 3.7 Ограничения идентичности (Заряна / Zaryana)

**Zaryana** — этап структурирования состояния, ограничивающий допустимую форму результата без уничтожения искажения.

**Общая идея**

Zaryana выполняет интерполяцию между:
- текущим состоянием `S` (после Collapse)
- структурированной формой `ψ(S)`

- Коэффициент структурирования

`Z = (1 - distortion) × (1 - K_ZARYANA_CORR × |corruption - 0.5|)`

- Структурирующая функция ψ(S)

Применяется покомпонентно к каждому параметру:

`ψ(S) = sign(S) × (|S| ^ K_ZARYANA_POWER)`

где:
- применяется к:
  - всем axes
  - всем meta, кроме distortion
- `sign(0) = 0`

- Интерполяция

`S_final = lerp(S, ψ(S), Z)`

где:
`lerp(a, b, t) = a + (b - a) × t`

- Работа с distortion

- `distortion` не изменяется
- `distortion = λ` переносится напрямую в результат

## Свойства этапа

- отсутствуют ветвления
- отсутствует clamp
- применяется ко всем компонентам состояния
- обеспечивает непрерывное структурирование

## Поведение системы

- `Z → 0` → состояние сохраняется (Morok доминирует)
- `Z → 1` → состояние полностью структурировано
- `0 < Z < 1` → плавный переход

## Эффекты ψ(S)

- подавляет экстремальные значения
- делает распределение более «устойчивым»
- сохраняет знак и направленность

## Конфигурационные параметры

(см. раздел 10.7)
- `K_ZARYANA_CORR`
- `K_ZARYANA_POWER`

## Связь с системой

- работает после Collapse
- не конфликтует с Morok
- не отменяет искажение, а структурирует его результат

## Инварианты этапа

- Zaryana — единственная точка структурирования состояния
- не изменяет distortion
- не нарушает структуру Vector
- не вводит новых параметров

Результат этапа: структурированное состояние, готовое к финальной нормализации (clamp).

12. **Final Clamp** (axes → [-1,1], meta → [0,1])

- порядок **строго фиксирован**
- запрещены:

  - перестановка этапов
  - повторное применение

### Дополнительные уточнения

- **Δ существует только внутри Process System** и не передаётся между вызовами
- **distortion вычисляется только на этапе Morok**
- **clamp применяется только один раз — после Zaryana**
- все промежуточные значения могут выходить за диапазоны
