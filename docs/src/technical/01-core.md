# 1. ЯДРО (CORE)

## 1.1 Принципы

Система основана на следующих принципах:

- Детерминизм (Determinism) – одинаковый входной набор параметров всегда приводит к одинаковому результату.
- Непрерывность (Continuity) – все параметры являются непрерывными. Дискретные состояния отсутствуют.
- Единая модель (Unified Model) – все сущности, эффекты и взаимодействия описываются через одну модель: вектор осей + мета-параметры.
- Отсутствие рецептов (No Recipes) – в системе отсутствуют фиксированные комбинации входов с заранее заданным результатом.
- Контекстная зависимость (Context Dependence) – результат определяется не только входными данными, но и контекстом их применения.
- Разделение слоёв (Separation of Layers) – входные данные, процесс обработки и результат разделены на независимые слои.

## 1.2 Инварианты

**Следующие свойства сохраняются на всех этапах обработки:**

**Единый поток обработки (Single Pipeline)** – все преобразования происходят в рамках одного пайплайна.

**Отсутствие уникальных правил (No Special Cases)** – в системе отсутствуют жёсткие условия (if/else), влияющие на результат. Все зависимости выражаются через параметры и функции.

**Ограниченность финальных параметров (Bounded Final Parameters)** – после финального clamp все параметры находятся в диапазонах:
  axes ∈ [-1, 1], meta ∈ [0, 1].
  В процессе вычислений допустим выход за пределы этих диапазонов.

**Разделение уровней (Separation of Layers)** – входные данные, процесс обработки и результат разделены на независимые слои.

**Иммутабельность результата (Immutable Result)** – финальный ресурс не изменяется после завершения пайплайна.

**Morok — единственный источник динамической нелинейности** –
  нелинейное искажение применяется только к приращению Δ на этапе Morok.

  Допускаются:

  - монотонные функции в адаптерах контекста;
  - вычисление λ с использованием нелинейных операций;
  - кусочно-линейные и композиционные эффекты Interaction Rules.

  Это не нарушает инвариант, так как:

  - Morok — единственный механизм, изменяющий динамику состояния;
  - остальные нелинейности не искажают Δ и не вводят хаотическое поведение.

**Отсутствие промежуточного clamp состояния** –
  clamp не применяется к состоянию S (axes, meta) внутри Process System.

  Разрешено:

  - использовать clamp только для служебных коэффициентов (например, λ);
  - использовать clamp в отдельных адаптерах, если это явно указано.

**Единая точка нормализации** –
  финальный clamp применяется **ровно один раз** после этапа Zaryana.

**Modifiers не являются частью состояния** –
  modifiers:

  - не входят в Vector;
  - не сохраняются в результате;
  - используются только как параметры вычислений.

**Distortion не является входным параметром** –
  distortion:

  - не передаётся из источников;
  - вычисляется только в Process System (в Morok);
  - сохраняется только в Result Vector.

**Композиционная нелинейность допустима** –
  последовательное применение линейных и кусочно-линейных операций может приводить к нелинейному поведению системы в целом.
  Это допустимо, так как не вводит новых типов преобразований.

**Детерминизм при экстремальных значениях** –
  даже при выходе параметров в «нестабильные зоны» система остаётся полностью детерминированной.


## 1.3 Единая модель

Любое состояние системы представляется как:

- вектор осей (axes)
- мета-параметры (meta)

Все преобразования выполняются над этими структурами. Никакие дополнительные скрытые состояния не допускаются.

## 1.4 Определение пайплайна

Преобразование данных происходит по фиксированному порядку:

Sources →
→ Input Assembly
→ Aggregation Refinement
→ Δ Calculation
→ Context Modifiers (контекстные коэффициенты)
→ Water Application
→ Axis Sign Modifiers (непрерывные модификаторы знаков осей)
→ Interaction Rules
→ Morok (искажение Δ → Δ_morok, S += Δ_morok)
→ Conflict Resolution
→ Collapse
→ Identity Constraints (Zaryana)
→ Final Clamp
→ Result Vector
→ Resource
→ Perception
→ UI

**Определения этапов:**

- **Δ Calculation** – вычисление приращения, используемого исключительно в Morok. Δ не является частью состояния и не сохраняется.
- **Context Modifiers** – мультипликативное применение коэффициентов k_axis и k_meta.
- **Water Application** – аддитивное изменение axes и meta выбранной водой.
- **Axis Sign Modifiers** – непрерывные поправки meta-параметров на основе знаков осей.
- **Morok** – единственный этап, изменяющий Δ нелинейно и влияющий на состояние через Δ_morok.
- **Final Clamp** – единственная точка нормализации всех параметров.

**Свойства пайплайна:**

- Пайплайн является линейным и строго упорядоченным.
- Каждый этап выполняется ровно один раз.
- Запрещены:
  - пропуск этапов;
  - изменение порядка;
  - повторное применение этапов.
- Все промежуточные значения могут выходить за допустимые диапазоны до этапа Final Clamp.
- Δ существует только внутри Process System и не передаётся между вызовами.

Пайплайн является инвариантом системы и не подлежит изменению без изменения всей модели.
