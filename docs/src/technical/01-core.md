# 1. ЯДРО (CORE)

## 1.1 Принципы

Система основана на следующих принципах:

- Детерминизм (Determinism) – одинаковый входной набор параметров всегда приводит к одинаковому результату.
- Непрерывность (Continuity) – все параметры являются непрерывными. Дискретные состояния отсутствуют.
- Единая модель (Unified Model) – все сущности, эффекты и взаимодействия описываются через одну модель: вектор осей + мета-параметры.
- Отсутствие рецептов (No Recipes) – в системе отсутствуют фиксированные комбинации входов с заранее заданным результатом.
- Контекстная зависимость (Context Dependence) – результат определяется не только входными данными, но и контекстом их применения.
- Разделение слоёв (Separation of Layers) – входные данные, процесс обработки и результат разделены на независимые слои.

## 1.2 Инварианты

**Следующие свойства сохраняются на всех этапах обработки:**

**Единый поток обработки (Single Pipeline)** – все преобразования происходят в рамках одного пайплайна.

**Отсутствие уникальных правил (No Special Cases)** – в системе отсутствуют жёсткие условия (if/else), влияющие на результат. Все зависимости выражаются через параметры и функции.

**Ограниченность финальных параметров (Bounded Final Parameters)** – после финального clamp все параметры находятся в диапазонах: axes ∈ [-1, 1], meta ∈ [0, 1]. В процессе вычислений допустим выход за пределы этих диапазонов.

**Разделение уровней (Separation of Layers)** – входные данные, процесс обработки и результат разделены на независимые слои.

**Иммутабельность результата (Immutable Result)** – финальный ресурс не изменяется после завершения пайплайна.

**Morok — единственный источник динамической нелинейности** – нелинейное искажение применяется только к приращению Δ на этапе Morok. Допускаются монотонные функции в адаптерах контекста, вычисление λ с использованием нелинейных операций, кусочно-линейные и композиционные эффекты Interaction Rules.

**Morok применяется один раз за вызов Process System** – при последовательной агрегации (fold) Morok не применяется на промежуточных шагах, а только один раз после финального шага свёртки.

**Никакой другой этап не вводит нелинейных искажений** – запрещено добавлять нелинейные преобразования в partial_process, Conflict Resolution, Zaryana или любые расширения.

**Отсутствие промежуточного clamp состояния** – clamp не применяется к состоянию S (axes, meta) внутри Process System. Разрешено использовать clamp только для служебных коэффициентов (например, λ в Morok) и в отдельных адаптерах, если это явно указано.

**Единая точка нормализации** – финальный clamp применяется **ровно один раз** после этапа Zaryana.

**Modifiers не являются частью состояния** – modifiers не входят в Vector, не сохраняются в результате, используются только как параметры вычислений.

**Distortion не является входным параметром** – distortion не передаётся из источников, вычисляется только в Process System (в Morok), сохраняется только в Result Vector.

**Композиционная нелинейность допустима** – последовательное применение линейных и кусочно-линейных операций может приводить к нелинейному поведению системы в целом.

**Детерминизм при экстремальных значениях** – даже при выходе параметров в «нестабильные зоны» система остаётся полностью детерминированной.

**Контекст замораживается внутри одного вызова Process System** – при последовательной агрегации контекст (time, world, ecosystem) не изменяется.

## 1.3 Единая модель

Любое состояние системы представляется как:

- вектор осей (axes)
- мета-параметры (meta)

Все преобразования выполняются над этими структурами. Никакие дополнительные скрытые состояния не допускаются.

## 1.4 Определение пайплайна (канонический порядок)

Преобразование данных происходит по фиксированному порядку:

Sources →
→ Input Assembly
→ Sequential Aggregation (fold) using partial_process # если порядок задан
→ Δ Calculation
→ Morok (один раз, после финального шага fold)
→ Conflict Resolution
→ Collapse
→ Identity Constraints (Zaryana)
→ Final Clamp
→ Result Vector
→ Resource
→ Perception
→ UI


**Определения этапов:**

- **partial_process** – Process System без этапа Morok (см. 3.1). Используется внутри fold для композиции ингредиентов.
- **Sequential Aggregation (fold)** – последовательное применение partial_process к каждому ингредиенту в заданном порядке. Начинается с нейтрального состояния (identity element). Контекст фиксирован на всё время fold.
- **Δ Calculation** – вычисление приращения, используемого исключительно в Morok. Δ не является частью состояния и не сохраняется.
- **Morok** – единственный этап, изменяющий Δ нелинейно. Применяется **один раз** после завершения fold.
- **Final Clamp** – единственная точка нормализации всех параметров.

**Свойства пайплайна:**

- Пайплайн является линейным и строго упорядоченным.
- Каждый этап выполняется ровно один раз (fold содержит внутреннюю итерацию, но она не является отдельным этапом пайплайна).
- Запрещены: пропуск этапов, изменение порядка, повторное применение этапов.
- Все промежуточные значения могут выходить за допустимые диапазоны до этапа Final Clamp.
- Δ существует только внутри Process System и не передаётся между вызовами.
- Контекст не изменяется внутри fold.

Пайплайн является инвариантом системы и не подлежит изменению без изменения всей модели.
