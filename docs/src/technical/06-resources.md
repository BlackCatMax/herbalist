# 6. ПОТОК РЕСУРСОВ

## 6.1 Система сбора (Harvesting)

Harvesting System — процесс получения ресурсов из мира. Преобразует сущность (Entity) в Resource (pre-process) с учётом контекста сбора.

**Вход:**
- Сущность (Entity) с BehaviorTags, `intensity` [0,1], `quality` [0,1]
- **Список активных сущностей в локации** (из Context)
- Контекст сбора: `time_of_day`, `season`, `moon_phase`, `toxicity`, `altitude`, `fertility`, `moisture`, `competition`, `disturbance`

**Выход:**
- Resource (pre-process) с BehaviorTags (унаследованные от сущности + добавленные от контекста + добавленные от окружающих сущностей), `intensity_final`, `quality_final`

### Процесс

**1. Копирование BehaviorTags от собираемой сущности**
Resource.tags = Entity.tags.copy()

**2. Добавление тегов контекста**

В соответствии с правилами из раздела 10.5 добавляются теги от:
- времени суток (`night`, `sun`, `dawn`, `dusk`)
- сезона
- фазы луны (`full_moon`, `new_moon`)
- биома (`forest`, `swamp`, `steppe`, `mountain`)
- погодных условий (`storm`, `wind`, `ice`)

for context_tag in get_context_tags(context):
    Resource.tags.add(context_tag, weight=1.0)

#### Таблица правил добавления тегов контекста

При сборе ресурса к его тегам добавляются следующие теги в зависимости от контекста:

| Условие | Добавляемый тег | Вес | Примечание |
|:---|:---|:---|:---|
| `time_of_day < 0.25 or time_of_day > 0.75` | `night` | 1.0 | Ночь |
| `0.25 ≤ time_of_day < 0.35` | `dawn` | 1.0 | Рассвет |
| `0.65 ≤ time_of_day < 0.75` | `dusk` | 1.0 | Сумерки |
| `0.45 ≤ time_of_day ≤ 0.55` | `sun` | 1.0 | Полдень |
| `moon_phase == 0.5` | `full_moon` | 1.0 | Полнолуние |
| `moon_phase == 0.0 or moon_phase == 1.0` | `new_moon` | 1.0 | Новолуние |
| `season ∈ [0.0, 0.25)` | `spring` | 1.0 | Весна |
| `season ∈ [0.25, 0.5)` | `summer` | 1.0 | Лето |
| `season ∈ [0.5, 0.75)` | `autumn` | 1.0 | Осень |
| `season ∈ [0.75, 1.0]` | `winter` | 1.0 | Зима |
| `biome == "forest"` | `forest` | 1.0 | Лес |
| `biome == "swamp"` | `swamp` | 1.0 | Болото |
| `biome == "steppe"` | `steppe` | 1.0 | Степь |
| `biome == "mountain"` | `mountain` | 1.0 | Горы |
| `moisture > 0.7` | `water` | 0.5 | Влажное место |
| `toxicity > 0.5` | `rotten` | 0.3 | Загрязнённое место |
| `altitude > 0.7` | `mountain` | 0.5 | Высокогорье |

Примечания:
- Вес тега умножается на интенсивность ресурса при суммировании в Input Assembly
- Несколько условий могут добавить один и тот же тег — веса суммируются
- Таблица может расширяться при добавлении новых биомов или погодных условий

**3. Добавление тегов от окружающих сущностей (Entity → Harvest Influence)**

def apply_entity_influence(resource, entities_in_location):
    for entity in entities_in_location:
        # Вес влияния ограничен
        influence = entity.intensity * K_ENTITY_INFLUENCE
        influence = clamp(influence, 0, K_ENTITY_INFLUENCE_MAX)
        
        for tag in entity.tags:
            resource.add_tag(tag, weight=influence)

**4. Расчёт коэффициентов контекста для интенсивности и качества**

# Коэффициенты от мира и экосистемы (см. разделы 5.4, 5.5)
k_axis_world = 1 - toxicity
k_axis_eco = fertility * (1 - 0.5 * competition) * (1 + 0.3 * moisture)

k_meta_world = 1 - 0.3 * toxicity - 0.2 * altitude
k_meta_eco = (1 - 0.4 * competition) * (1 - 0.5 * abs(moisture - 0.5)) * (1 - 0.3 * disturbance)

# Коэффициенты от времени (опционально, см. раздел 5.3)
k_axis_time = 1 + 0.3 * sin(2π * time_of_day)
k_meta_time = 1 + 0.2 * cos(2π * season)

# Итоговые коэффициенты с ограничением
k_intensity = k_axis_world * k_axis_eco * k_axis_time
k_intensity = clamp(k_intensity, 0.5, 1.5)

k_quality = k_meta_world * k_meta_eco * k_meta_time
k_quality = clamp(k_quality, 0.5, 1.5)


**5. Применение коэффициентов**

intensity_final = base_intensity * k_intensity
quality_final = base_quality * k_quality


**6. Формирование Resource (pre-process)**

Resource = {
    tags: List[BehaviorTag],      # исходные + контекстные + от сущностей
    intensity: float,             # intensity_final ∈ [0, 1]
    quality: float,               # quality_final ∈ [0, 1]
    altitude_bonus: float         # 0.2 * smoothstep(0.7, 1.0, altitude)
}

### Порядок применения

1. Копирование тегов от собираемой сущности
2. Добавление тегов контекста
3. Добавление тегов от окружающих сущностей
4. Расчёт коэффициентов интенсивности и качества
5. Применение коэффициентов
6. Формирование Resource

### Сбор воды

Вода не является ресурсом (Resource) в смысле BehaviorTags, но может быть собрана и сохранена в инвентаре как **расходная основа**. Сбор воды возможен из следующих источников:

- **Родник, река, болото** – при наличии в инвентаре пустой ёмкости (фляги, бурдюка) игрок получает 1 единицу соответствующего типа воды.
- **Дождевая вода** – если игрок оставляет ёмкость на открытом месте во время дождя (проверяется через погодную систему), каждые N игровых минут добавляется 1 единица дождевой воды.
- **Роса** – собирается специальным предметом (льняная ткань) с высоких трав в утренние часы (time_of_day в диапазоне 0.2–0.3) при moisture > 0.5 и температуре выше нуля.
- **«Живая» вода** – создаётся путём обряда освящения на капище. Требует: 1 единица обычной воды, 1 ресурс с тегом `blessed` (например, ветка дуба). Результат: 1 единица живой воды.
- **«Мёртвая» вода** – создаётся путём обряда омертвления на кургане или в болоте в полночь (time_of_day = 0 или 1). Требует: 1 единица болотной воды, 1 ресурс с тегом `grave` или `rotten`. Результат: 1 единица мёртвой воды.

Все собранные единицы воды добавляются в инвентарь в отдельный раздел «Основы / Вода» (см. раздел 6.4). Сбор воды подчиняется тем же правилам детерминизма, что и сбор растений: одинаковые условия всегда дают одинаковый результат.

### Конфигурационные параметры

| Константа | Значение | Описание |
|-----------|----------|----------|
| `K_ENTITY_INFLUENCE` | 0.5 | Базовый множитель влияния сущности на сбор |
| `K_ENTITY_INFLUENCE_MAX` | 0.3 | Максимальное влияние одной сущности |

### Инварианты системы сбора

- Не выполняет преобразований Vector
- Не использует Process System
- Не вычисляет axes и meta
- Не генерирует `distortion`
- Влияние сущностей ограничено и детерминировано
- Влияние сущностей не может превышать `K_ENTITY_INFLUENCE_MAX`
- Вода не является Resource и не имеет BehaviorTags

## 6.2 Система алхимии (Alchemy System)

Alchemy System определяет, **как входные ресурсы объединяются** и формируют веса для Input Assembly, а также задаёт процессные modifiers.

### Роль системы

- определяет веса `weight_i` для агрегации
- формирует `pressure`
- управляет порядком и пропорциями
- не изменяет axes и meta напрямую

### Вход

- набор ресурсов (Resources)
- порядок добавления (опционально)
- пропорции (опционально)
- выбранная вода

### Выход

- веса `weight_i` для каждого ресурса
- modifier `pressure`

### Последовательная агрегация (fold) — если порядок задан

Если задан порядок ингредиентов, агрегация выполняется последовательно:

#### Нейтральное состояние (Identity Element)

S0:
axes = (0, 0, 0, 0)
potency = 0
purity = 1
stability = 1
resonance = 0.5
corruption = 0


Это состояние удовлетворяет: `Process(S0, I, w) = Process(I, w)` для любого I, w.

#### Алгоритм fold

1. Контекст (time, world, ecosystem) вычисляется **один раз** перед первым шагом и остаётся **неизменным** на протяжении всей свёртки. Мир не меняется внутри одной варки.

2. Для каждого ингредиента i от 1 до N (в заданном порядке):
   - `S_i = partial_process(S_{i-1}, I_i, weight_i, context, modifiers)`
   - где `partial_process` — это полный Process System **без этапа Morok** (см. 3.1, 3.5). Все остальные этапы (Context Modifiers, Water Application, Axis Sign Modifiers, Interaction Rules, Conflict Resolution, Collapse, Zaryana, Final Clamp) сохраняются.

3. После завершения всех шагов:
   - Вычисляется Δ по финальному состоянию S_N (по формулам из раздела 3.2).
   - Применяется Morok (один раз) — см. раздел 3.5.
   - Применяются остальные этапы (Conflict Resolution, Collapse, Zaryana, Final Clamp).

#### Замечание о порядке

Порядок добавления влияет на результат, так как каждый шаг зависит от предыдущего состояния. Это делает операцию **некоммутативной**, но сохраняет детерминизм и stateless.

### Коммутативный случай (порядок не задан)

Если порядок не задан или все веса равны, используется коммутативная агрегация (суммирование) без учёта последовательности:

`weight_i = base_i / Σ(base_j)`

### Фактор порядка (только для коммутативного случая)

Если используется коммутативная агрегация, можно влиять на веса через порядок, но без последовательного применения. Для этого используется:

`order_factor_i = 1 + K_ORDER_INFLUENCE × ((p - 1) / N)`

где p — позиция (1-index). Однако этот механизм не даёт такого же эффекта, как fold. Рекомендуется использовать fold для реального влияния порядка.

### Формирование pressure

`pressure = K_PRESSURE_BASE + K_PRESSURE_COUNT × (N / N_max)`

(Параметры `temperature`, `duration`, `method` исключены, так как не входят в модель. Если они нужны для геймплея, они должны влиять через context или modifiers.)

### Конфигурационные параметры

(см. раздел 10.7)

- `K_ORDER_INFLUENCE` (только для коммутативного случая)
- `K_PRESSURE_BASE`
- `K_PRESSURE_COUNT`
- `N_max`

### Инварианты этапа

- веса определяются до Input Assembly
- pressure формируется один раз
- отсутствует влияние на axes/meta напрямую
- система не содержит скрытых состояний
- **fold использует partial_process, не содержащий Morok**
- **контекст заморожен на время fold**

Результат — подготовленные веса и modifiers для передачи в Input Assembly и Process System.

## 6.3 Система ресурсов (Resources System)

Управляет структурой и состоянием ресурсов.

**Типы ресурсов:**
- Resource (pre-process) – до алхимии, содержит BehaviorTags, интенсивность, качество.
- Resource (final) – после Process System, содержит axes и meta (включая `distortion`).

**Преобразование Result Vector → Resource (final):**
Resource.axes = ResultVector.axes
Resource.meta = ResultVector.meta (включая distortion)

Преобразование является структурным отображением (копированием). Никакие значения не изменяются.

**Свойства Resource (final):**
- иммутабелен (не изменяется после создания)
- любые изменения создают новый Resource
- при повторном использовании Resource как ингредиента его `distortion` игнорируется (обнуляется в Input Assembly)

## 6.4 Система хранения (Storage System)

Storage System отвечает за хранение ресурсов (как pre-process, так и final).

**Функции:**
- инвентарь игрока
- контейнеры мира
- передача и доступ

**Свойства:**
- не изменяет содержимое Resource
- не влияет на параметры
- не участвует в вычислениях

### Хранение воды

Вода хранится в специальном разделе инвентаря «Основы / Вода». Каждый тип воды (родниковая, речная, болотная, дождевая, роса, живая, мёртвая, а также обычная вода) представлен отдельной записью с целочисленным количеством (например, «Родниковая: 3»). Обычная вода считается бесконечной и не отображается в инвентаре (или отображается с символом ∞).

**Ограничение ёмкости:**  
Общее количество всех типов воды (кроме обычной) не может превышать `max_water_capacity`. Начальное значение = 3. При попытке добавить воду сверх лимита сбор невозможен (игрок получает сообщение «Нет места для воды»).

**Увеличение ёмкости:**  
Максимальная ёмкость увеличивается через систему прогрессии (улучшение фляги, покупка бурдюка, изучение навыков). Максимальное значение ограничено конфигурационной константой (например, 20).

Вода иммутабельна: она не изменяется со временем и не портится. При использовании в алхимии количество соответствующего типа уменьшается на 1. Если количество достигает 0, запись удаляется из инвентаря (или скрывается).

## Инварианты потока ресурсов

- Ни одна система в этом слое (кроме опосредованно, через передачу данных) не выполняет преобразования Vector.
- Все вычисления происходят только в Process System.
- Resource передаётся между системами без изменения (иммутабельность).
- Любые изменения создают новый Resource.
- `distortion` не создаётся в Harvesting или Alchemy; он появляется только в Process System.
- При повторном использовании Resource его `distortion` обнуляется.
