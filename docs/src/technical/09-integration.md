# 9. ИНТЕГРАЦИЯ

## 9.1 Полный пайплайн (Unified Pipeline)

Полный пайплайн объединяет все системы в единый детерминированный процесс.

## Последовательность

### Input Layer

1. **Alchemy System (6.2)**
     → вычисляет `weight_i`, `pressure`

2. **Input Assembly (4.6)**
     → формирует `axes`, `meta`, `modifiers`, `context`

### Process System

3. **Aggregation Refinement (3.2)**
     → подготовка состояния S

4. **Δ Calculation (3.2)**
     → вычисление приращения Δ

5. **Context Modifiers (3.3, 5.6, 5.7)**
     → применение `k_axis_total`, `k_meta_total`
     → применение altitude

6. **Water Application (3.3, 5.8)**
     → аддитивные изменения

7. **Axis Sign Modifiers (3.3)**
     → непрерывные поправки

8. **Interaction Rules (3.4)**
     → системные взаимодействия

9. **Morok (3.5)**
     → вычисление `λ`, получение `Δ_morok`, обновление S

10. **Conflict Resolution (3.6)**
      → сглаживание осей

11. **Collapse (3.6)**
      → деградация при низкой stability

12. **Zaryana (3.7)**
      → структурирование состояния

13. **Final Clamp (2.5)**
      → нормализация

### Output Layer

14. **Result Vector (7.1)**
      → финальная структура

15. **Resource Generation**
      → создание игрового объекта

16. **Perception System**
      → интерпретация (текст, визуал)

17. **UI**
      → отображение игроку

### Memory Update

18. **Memory System (8.1)**
      → обновление `last_distortion`, `corruption_memory`, `clarity`

## Свойства пайплайна

- полностью детерминирован
- не содержит ветвлений
- выполняется последовательно
- все этапы выполняются ровно один раз

## Гарантии

После завершения:
- все значения нормализованы
- результат пригоден для использования
- память обновлена

## Инварианты

- структура пайплайна фиксирована
- порядок этапов неизменяем
- отсутствуют скрытые стадии
- все системы связаны только через явно определённые параметры

Результат — единый формализованный процесс преобразования входных данных в игровой результат.


## 9.2 Границы системы

Система разделена на уровни:

| Уровень | Компоненты | Ответственность |
|---------|------------|----------------|
| **Input Layer** | Sources, Entities, Resource (pre-process), BehaviorTags | Предоставление исходных данных |
| **Transformation Layer** | Process System (все преобразования Vector) | Математическая обработка |
| **Context Layer** | Time, World, Ecosystem, окружение | Формирование коэффициентов (не изменяет данные напрямую) |
| **Output Layer** | Result Vector, Resource (final), Perception, UI | Формирование и отображение результата |
| **Meta Systems** | Memory, Pressure, Knowledge, Progression | Косвенное влияние через modifiers/context/perception |

**Правило границ:**
- Каждый слой имеет чёткую ответственность.
- Не дублирует функции других слоёв.
- Не вмешивается в чужую логику.
- Нет прямых переходов между несвязанными слоями.

## 9.3 Правила потока данных

Данные движутся только в одном направлении:
Input → Process → Output

**Запрещено:**
- обратное влияние Output на Process
- изменение Resource после создания
- использование UI или Perception в вычислениях
- циклические зависимости
- параллельные обходы пайплайна
- скрытые связи

**Допустимо:**
- Meta Systems влияют на будущие вычисления (через modifiers, context)
- Context влияет через коэффициенты (k_axis, k_meta)
- Modifiers передаются в Process System
- Perception использует Resource и modifiers, но не изменяет их

**Целостность данных:**
- На каждом этапе структура Vector сохраняется.
- Параметры находятся в допустимых диапазонах (после финального clamp).

## 9.4 Правила расширения

Система допускает расширение только через определённые точки.

**Допустимые способы расширения:**
1. Добавление новых BehaviorTags (с маппингом в таблицу).
2. Добавление новых Sources.
3. Расширение Context (новые параметры времени, мира, экосистемы) с соответствующими адаптерами.
4. Добавление modifiers (новые внешние параметры).
5. Расширение Perception (новые способы визуализации).

**Ограничения:**
- Запрещено изменять структуру Vector (axes и meta).
- Запрещено добавлять новые этапы в Pipeline.
- Запрещено вводить уникальные правила (if/else) в Process System.
- Запрещено изменять существующие зависимости без пересмотра CORE.
- Запрещено изменять формулы Morok, Zaryana, Interaction Rules.

**Правило совместимости:**
Любое расширение:
- должно сохранять инварианты CORE
- не нарушать детерминизм
- не изменять поведение существующих элементов
- проходить все правила валидации
