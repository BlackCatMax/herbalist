# FIX PROMPT — SYSTEM CONSISTENCY REPAIR

Ты получил результат полного аудита системы (список проблем с типами, локациями и исправлениями).

Твоя задача — **внести исправления в документы**, чтобы привести систему к полной согласованности.

---

# ❗ ГЛАВНЫЙ ПРИНЦИП

Ты НЕ имеешь права:

* изменять логику системы
* “улучшать” дизайн
* перепридумывать формулы
* упрощать модель
* добавлять новые механики

Ты ОБЯЗАН:

* исправлять ТОЛЬКО выявленные проблемы
* сохранять исходную архитектуру
* строго соблюдать CORE

---

# 🧠 CORE (АБСОЛЮТНЫЙ ПРИОРИТЕТ)

Все изменения ДОЛЖНЫ:

* подчиняться CORE из technical.md
* не нарушать инварианты
* не вводить новые нелинейности
* не создавать скрытые состояния
* не менять pipeline

Если исправление конфликтует с CORE:
→ исправление ЗАПРЕЩЕНО
→ нужно изменить формулировку, а не систему

---

# 🔧 РЕЖИМ РАБОТЫ

Ты работаешь как **системный хирург**, а не дизайнер:

* точечные правки
* минимально необходимые изменения
* никаких побочных эффектов

---

# 📦 ВХОД

Ты получаешь:

1. Список проблем (из AUDITOR)
2. Три документа:

# 🔁 АЛГОРИТМ ИСПРАВЛЕНИЯ

Для КАЖДОЙ проблемы:

---

## ШАГ 1 — ВАЛИДАЦИЯ

Проверь:

* проблема реально существует
* локация корректна
* исправление не нарушает CORE

Если есть сомнение:
→ считать проблему валидной

---

## ШАГ 2 — ОПРЕДЕЛЕНИЕ МИНИМАЛЬНОГО FIX

Определи:

* какой именно кусок текста нужно изменить
* можно ли исправить через:

  * уточнение формулировки
  * добавление ограничения
  * удаление противоречия

Запрещено:

* переписывать раздел целиком без необходимости
* дублировать логику

---

## ШАГ 3 — ПРИМЕНЕНИЕ ИСПРАВЛЕНИЯ

Ты обязан:

* дать **ТОЧНУЮ замену текста**
* указать:

  * файл
  * раздел
  * старый фрагмент
  * новый фрагмент

---

# ⚙️ СПЕЦИАЛЬНЫЕ ПРАВИЛА

## 1. Pipeline — СВЯЩЕНЕН

Запрещено:

* менять порядок этапов
* добавлять новые этапы
* удалять этапы

Разрешено:

* уточнять формулировки
* синхронизировать между документами

---

## 2. Morok — ЕДИНСТВЕННАЯ НЕЛИНЕЙНОСТЬ

Любое исправление должно гарантировать:

* никакой другой этап не искажает Δ
* нет скрытых нелинейностей

---

## 3. Clamp — ОДИН РАЗ

Проверить, что после фиксов:

* clamp используется только в конце
* нет промежуточного clamp состояния

---

## 4. Modifiers — НЕ СОСТОЯНИЕ

Проверить:

* modifiers не сохраняются
* не превращаются в meta
* используются только в разрешённых этапах

---

## 5. Distortion

Должно быть явно:

* где создаётся
* где отсутствует
* где сохраняется

---

## 6. НИКАКИХ СКРЫТЫХ СИСТЕМ

Если при фиксе появляется:

* новая логика
* новая зависимость
* новая система

→ это запрещено

---

# 🔁 POST-FIX ПРОВЕРКА (ОБЯЗАТЕЛЬНО)

После применения ВСЕХ фиксов ты обязан:

---

## 1. Повторная проверка pipeline

* порядок не изменился
* все этапы присутствуют
* нет дублей

---

## 2. Проверка CORE

Ответить явно:

* все ли инварианты соблюдены?
* есть ли нарушения?

---

## 3. Проверка систем

Проверить:

* Morok
* Zaryana
* Δ
* Modifiers
* Context
* Memory
* World
* Perception

Все должны:

* быть определены
* быть связаны
* не противоречить друг другу

---

## 4. Проверка на побочные эффекты

Ответить:

* не сломал ли один фикс другой?
* не появились ли новые противоречия?
