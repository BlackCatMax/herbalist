# Проверка документации Herbalist

Быстрый вызов проверки, написанной 2026-09-14. Сам скрипт только читает;
смысл проверок и что делать с находками — `docs/maintenance/DOCS_AUDIT_CHECKLIST.md`,
правила правки — `docs/maintenance/DOCS_UPDATE_PROMPT.md`. Этот скилл не
дублирует их, а говорит, как быстро прогнать и доложить.

## Аргумент

- пусто или `quick` — скрипт, доклад;
- `C06,C09` — только эти проверки (`--only`);
- `full` — скрипт и ручная часть чек-листа (шаг 2) по всем разделам;
- `fix` — скрипт, затем исправить механическое по правилам промпта, повторный прогон;
- `strict` — считать провалом и предупреждения (`--strict`).

## Шаги

1. Из корня репозитория (Git Bash):

   ```bash
   PYTHONIOENCODING=utf-8 py tools/docs_audit/audit_docs.py [--only C06,C09] [--strict]
   ```

   Код выхода 1 — есть ошибки. Отчёт — `build/docs_audit/report.md`; читать
   его, а не только консоль: в консоли одни счётчики.
2. Трогал сам скрипт или его тесты — сначала:

   ```bash
   PYTHONIOENCODING=utf-8 py -m unittest tools/docs_audit/test_audit_docs.py
   ```

3. Сравнить с эталоном ниже. Новое против эталона — главное в докладе.
4. Режим `fix`: исправлять только однозначное (ссылки, опечатки в заголовках,
   форма фронтматтера, индексы, справочники); смысловое и лор — списком
   вопросов, не править. Удаление — только после проверки входящих ссылок.
   Затем повторный прогон: ошибок 0, предупреждений не больше исходного.
   Трогал код (комментарии тоже) — сборка и два прогона автотестов по
   `docs/verification/ENGINE_VERIFICATION_GUIDE.md`, уровень 1.
5. Ложная находка — не обходить, а дописать исключение в константу скрипта
   (`ENGINE_NAMES`, `PROPOSED_NAMES`, `CARD_ENUMS`, `NOT_IN_WORLD_PREFIXES`) с
   причиной и тестом в `test_audit_docs.py`.

## Доклад пользователю

По-русски, коротко:

- итог: ошибок / предупреждений / инфо и сравнение с эталоном;
- **новые** находки — по проверкам, с `файл:строка` и сутью;
- что исправлено (в режиме `fix`) и что оставлено автору с причиной;
- известные пять из эталона — одной строкой, не перечислять заново.

Не называть документацию «в порядке» по одному скрипту: ручная часть
чек-листа (смысл, противоречия глав, лор против чисел) скриптом не
проверяется — в режиме `quick` так и сказать.
