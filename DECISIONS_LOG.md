# DECISIONS_LOG — раунд «Анализ несоответствий лор/дизайн/код»

Дата: см. дату коммита. Формат: пункт → решение → приоритет.

## 1. Навь vs Морок — критично

**Решение:** закреплено чёткое различение.
- **Морок** — локальный, временный акт искажения восприятия (высокий
  `Distortion` в конкретной клетке/предмете здесь и сейчас).
- **Навь** — устойчивое глобальное состояние: `Distortion` клетки/региона
  держится выше порога длительное время, меняет поведение сущностей.

Не «игрок сам догадается» — путаница в терминологии разработчиков это
баг, недостоверным должно быть восприятие персонажа, не словарь автора.
`02_Setting`/`03_Narrative` требуют правки под это различение,
`01_Glossary` — новая/обновлённая статья. Точный числовой порог
«сколько Distortion держится, чтобы считаться Навью» — не определён
этим решением, отдельный черновой параметр.

## 2. PerceiveClass — важно, вариант А (реализовать)

**Решение:** реализовать, узко. Подмена названия/иконки предмета — только
при высоком локальном `Distortion`, только на визуально похожий
ингредиент того же биома (не любой случайный), вероятностная, не
постоянная. Обосновано тем, что вся игра построена на `S_Perceived` как
центральной теме — герой не должен быть единственным, кого Морок не
обманывает по сути предмета, только по цифрам (`16_Entity_Manifestation
§16.6` уже называл это открытым долгом).

## 3. Камень-оберег в ритуальной варке — критично, баг

**Решение:** чинить. Списание заряда добавить в `TryAdvanceRitual` тем же
путём, что уже работает в `ApplyAlchemy`. Не дизайн-развилка — бесконечная
защита ломает саму идею риска в инвестиции
(`20_Investment_And_Progression §20.2`). Нужен отдельный тест на именно
ритуальный путь — старый тест эту дыру не ловил.

## 4. Ночная нечисть, единый нудж vs пять — желательно, вариант А для v1

**Решение:** для v1 — вариант А (случайный «лик» из пяти существ выбирается
на ночь, только текст в логе меняется, эффект общий, ноль нового кода).
Полное разделение на пять условий (вариант Б) — реальная будущая глубина,
но противоречит принципу сессии «не заводить механику ради вкуса, когда
можно переиспользовать». Зафиксировать вариант Б явно в `ROADMAP.md` как
кандидат v2, не оставлять молчаливо забытым.

## 5. Момент получения артефакта — важно, решено

**Решение:** физический актор в мире (переиспользовать паттерн
`AMemoryFragmentActor`) рядом с проявленной сущностью после срабатывания
триггера, подбирается вручную — не тихое появление в инвентаре. Держит
принцип «мир читается ногами, не уведомлениями», уже общий для игры.

## 6. Сенсорное искажение (визуал/звук) — желательно, но дёшево — делать

**Решение:** привязать цветокоррекцию поста к `CurrentGlobalDistortion`
через уже существующий `MPC_WorldStateFields` — почти бесплатно, немедленная
атмосферная отдача. Звук (гул/шёпот при высоком Distortion) — отдельным,
более поздним заходом, требует реальных звуковых ассетов, не только
параметра.
